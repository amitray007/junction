# 41.2 — CLI Full Access: recursive --help extractor (sandbox-always)

**Builder: Sonnet.** Depends on 41.1 (`ExtractedCliSchema`, `CliSchemaNode`). Design: `docs/specs/2026-07-16-cli-exploratory-mode.md` §5 Q3/Q4/Q5. Read the sandbox mechanics in `packages/core/src/sandbox/{sandbox.ts,exec.ts}` before starting.

## What / why

Given a pinned absolute `binaryPath` + a platform `CliPolicy`, produce an `ExtractedCliSchema` by running the binary's `--help` **recursively, sandboxed, credential-free, no network**, and parsing each node's help text. This is the "Junction learns the CLI once" engine.

## Interfaces

New file `packages/core/src/sources/cli/extract.ts`:

```ts
export interface HelpExtractor {
  /** Parse one node's raw --help text into structured fields. Returns parsed:false + rawHelp on failure. */
  parseHelp(rawHelp: string, path: string[]): ParsedHelpNode
}

export const genericHelpExtractor: HelpExtractor  // best-effort parser (below)

export function extractCliSchema(args: {
  binaryPath: string
  policy: CliPolicy            // platform-level; extraction OVERRIDES to no-cred/no-net/read-only (see below)
  sandbox: Sandbox            // injected (from createSandbox())
  extractor?: HelpExtractor   // defaults to genericHelpExtractor
  ceiling?: ExtractCeiling    // defaults below
}): ResultAsync<ExtractedCliSchema, SandboxError>

export type ExtractCeiling = { maxDepth: number; maxProbes: number; perProbeTimeoutMs: number; wallClockMs: number }
export const DEFAULT_CEILING: ExtractCeiling = { maxDepth: 5, maxProbes: 400, perProbeTimeoutMs: 10_000, wallClockMs: 300_000 }

/** Lazy single-node probe for on-demand exploration when help is called on an unexplored node (Fable Q4). */
export function probeNode(args: { binaryPath: string; policy: CliPolicy; sandbox: Sandbox; path: string[]; extractor?: HelpExtractor }): ResultAsync<CliSchemaNode, SandboxError>
```

## The safe-probe invocation (Fable Q3 — binding)

Every probe runs `runCommand([binaryPath, ...path, "--help"], probePolicy)` where `probePolicy` is DERIVED from the platform policy but HARDENED to the safe-probe class:
- `allowNet: []` (no network),
- **no credential env** — do NOT call `prepareCredential`; `env` carries only non-secret `envAllow` statics (and never a `*_TOKEN/_SECRET/_KEY` key),
- `writePaths: []` (read-only),
- `readPaths`: minimal — the binary's own dir is granted by the sandbox already; keep cwd within a scratch/tmp read path. Reuse the platform policy's `cwd`/`readPaths` but strip writePaths.
- `timeoutMs: min(perProbeTimeoutMs, policy.timeoutMs)`.

This is the invocation class Fable ruled safe (pinned binary + `--help` + no creds + no net + read-only). It is exempt from the "cli not-verifiable" rule (that rule now scopes to credentialed+networked calls only — note this in a comment referencing verify-credential.ts:246).

## The recursion (Fable Q4 — binding)

BFS or DFS from root (`path: []`):
1. Probe `--help` for the node. If the spawn errors/times out or output is capped, mark `parsed:false`, store whatever `rawHelp` came back (may be empty), `explored:true` (we DID probe it), and stop recursing that branch.
2. Parse with the extractor → fill fields, set `parsed`.
3. Compute `helpHash` = hash of normalized rawHelp (trim, collapse whitespace). **Loop detection:** if this node's `helpHash` equals any ANCESTOR's, do not recurse into its subcommands (`explored:true`, but children omitted) — prevents `foo help help help…` cycles.
4. For each discovered subcommand, if `depth < maxDepth` AND `probeCount < maxProbes` AND `elapsed < wallClockMs`: enqueue a child probe. Else: add the child as a node with `explored:false` (Fable: never abort — defer to lazy probing) and set the top-level `truncated:true`.
5. Children that were enqueued but not reached before a ceiling → `explored:false`.

`probeNode` is step 1-3 for a single path, used later (41.3) when `help` is called on an `explored:false` node.

## The generic parser (Fable Q5 — best-effort + raw fallback)

`genericHelpExtractor.parseHelp` handles common conventions seen in gh/git/docker/kubectl help:
- A `Usage:` / `USAGE` line → `usage`.
- A leading paragraph before the first section → `description`.
- A `Commands:` / `Available Commands:` / `SUBCOMMANDS` section → `subcommands` (name = first token, summary = rest of line).
- A `Flags:` / `Options:` / `FLAGS` section → `flags` (parse `-t, --title <val>` shapes: alias, name, takesValue = presence of `<...>`/`=`/ALLCAPS arg).
- Positionals from the usage line's `<arg>` tokens where feasible.
- If NONE of usage/commands/flags are found → `parsed:false`, keep `rawHelp`. **Never throw; never drop.**

Keep it a pure function over a string — no I/O. Design so a per-CLI or LLM extractor can implement `HelpExtractor` later (pluggable, Junction core stays LLM-free).

## Constraints

- **Sandbox-always:** extraction NEVER shells out directly — always `sandbox.runCommand`. Inject the `Sandbox` so tests use a fake. No `child_process` import in this file.
- No credential, no network in probe policy — assert it in tests.
- Bound everything (depth/probes/timeout/wall-clock). Loop-detect via help hash.
- Pure parser (no I/O). Typed errors. Single-purpose file. `docs/rules/`.
