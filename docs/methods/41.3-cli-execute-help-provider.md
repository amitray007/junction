# 41.3 — CLI Full Access: execute + help provider tools

**Builder: Sonnet.** Depends on 41.1 (schema/`isFullAccess`) + 41.2 (`probeNode` for lazy exploration). Design: `docs/specs/2026-07-16-cli-exploratory-mode.md` §5 Q2/Q3. Read `packages/core/src/sources/cli/provider.ts` fully first — you are ADDING a full-access branch, not changing declared behavior.

## What / why

Make `createCliProvider` serve a full-access connection as two generic tools — `execute` + `help` — plus any `shortcuts` (declared tools). For a declared connection, behavior is byte-identical to today.

## Interfaces

In `packages/core/src/sources/cli/provider.ts`, branch on `isFullAccess(connection)`:

### Declared mode
Unchanged — the existing `byName` map + 1:1 `providerTools` + `callTool`.

### Full-access mode

`listTools()` returns:
- `execute` — `{ name: "execute", description: "Run a <binaryName> command. Provide argv AFTER the binary; the binary is fixed.", inputSchema: { type:"object", properties: { args: {type:"array", items:{type:"string"}}, stdin:{type:"string"} }, required:["args"] }, annotations: { readOnlyHint:false, destructiveHint:true, openWorldHint:true } }`
- `help` — `{ name:"help", description:"Look up what a <binaryName> command can do — flags, subcommands, usage.", inputSchema: { type:"object", properties: { path: {type:"array", items:{type:"string"}} } }, annotations: { readOnlyHint:true } }`
- one ProviderTool per `shortcuts` entry (reuse the existing declared-tool projection — same `buildInputSchema`).

`callTool(rawName, rawArgs)`:
- `rawName === "execute"` → **execute path** (below).
- `rawName === "help"` → **help path** (below).
- else → look up in `shortcuts` byName (existing declared machinery, incl. flag-injection guard + `buildArgv`); `tool-not-found` if absent.

### execute path (Fable Q2 — binding)
1. Validate `rawArgs.args` is `string[]`; validate `stdin` is a string if present. Reject non-arrays with `invalid-args`.
2. **Element guards:** each element must be a string, length ≤ some cap (reuse the 4096 maxLength ceiling), and pass a control-char check. Cap the number of elements (e.g. 256) to bound argv. NO shell metachar rejection needed on values (there is no shell) — but reject NUL/newline in any element (they can break the sandbox profile / argv).
3. Build `argv = [connection.binaryPath, ...args]`. **binaryPath is pinned** — agent never supplies argv[0].
4. Build the runtime policy from `connection.policy`, and here (unlike extraction) **inject the credential** via the existing `prepareCredential` path (env or file kind) — execute is the credentialed, networked, side-effecting invocation. `allowNet` = the platform policy's allowlist.
5. `createSandbox().andThen(sb => sb.runCommand(argv, policy))`.
6. Return `{ exitCode, stdout, stderr, truncated: outputCapped ?? false, durationMs }` as the tool result (structure it as the ToolResult content). Secrets never appear in argv/results by construction.
7. **Audit:** ensure the existing audit hook records the full argv (the audit emit happens in the proxy/adapter layer via `emitToolCall`; confirm execute's argv is captured — if the audit currently logs only tool name + args, the `args` array IS the argv, so it's captured. Add a note/test.)

### help path (Fable Q2/Q4 — binding)
1. `path = rawArgs.path ?? []` (validate string[]).
2. Walk `connection.schema.root` to the node at `path`. If not found → `invalid-args` ("no such command path").
3. If the node is `explored:false` → **lazy probe** it now via `probeNode` (41.2), same safe-probe class (no creds/net), persist the result back into the connection's schema **if a persistence hook is available** (see note), and use the freshly probed node. If the sandbox is unavailable, return the node as-is with `explored:false` (honest).
4. Return **one node + shallow child index** (Fable Q2): `{ path, parsed, description, usage, flags, positionals, subcommands: node.subcommands.map(c => ({ name: last(c.path), summary: c.description })), rawHelp: node.parsed ? undefined : node.rawHelp }`. Do NOT return the full recursive subtree.

> **Persistence note:** the provider is connect-per-call and may not own a write path back to the DB. For this slice, lazy-probe results may be returned without persisting (correctness first). If a clean persistence seam exists (a callback passed to `createCliProvider`), wire it; otherwise leave a `docs/futures/revisit-when.md` entry: "persist lazy-probed CLI nodes when the provider gains a write-back seam." Do not force a DB dependency into `core/sources/cli`.

## Constraints

- Declared-mode behavior **byte-identical** — all existing provider tests pass.
- `execute` never lets the agent set argv[0]; binary is pinned.
- Extraction/help probes = no creds/no net; execute = credentialed/networked (the two invocation classes stay distinct).
- No shell. Typed errors. `docs/rules/`.
