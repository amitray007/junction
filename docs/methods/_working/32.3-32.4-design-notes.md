## 32.3 MASTER-KEY ROTATION
- Backend detect via `store.backend` (store.ts:14). keyring → REFUSE (hint: JUNCTION_STORE=file if a file vault exists). file → proceed.
- New core `rotateMasterKey(paths,env) → {tier, newKeyForOperator?}` in credentials/rotate-master-key.ts.
- ATOMIC ORDER (the one unavoidable non-atomic step made RECOVERABLE):
  1 acquire .credentials.lock (encrypted-file-store.ts:62)
  2 resolve OLD key + TIER
  3 decrypt ALL entries (abort if any fails — no silent drop)
  4 gen NEW key randomBytes(32)
  5 re-encrypt all → NEW tmp file (fresh IV/entry, AAD=secretRef), 0600
  6 round-trip verify tmp under NEW key (byte-equal) — abort+unlink on fail
  7 persist OLD key to sidecar `.master.key.old-<rand>` (0600) BEFORE overwrite
  8 rename live→credentials.enc.json.pre-rekey ; rename tmp→live
  9 install NEW key at SAME tier (file: writeFile0600 master.key / keyring: setPassword / env: can't)
  10 verify resolveMasterKey+open live under NEW key
  11 success: delete old-key sidecar, KEEP pre-rekey backup (0600); FAIL at 8-10: restore pre-rekey + reinstall old key from sidecar
  + recoverInterruptedRekey(paths) runs before store open on boot (sidecar+pre-rekey present → auto-restore)
- TIER install policy (never downgrade posture): file→overwrite master.key; keyring→overwrite keyring entry; env-raw→CAN'T install, FORK below; env-passphrase→--new-passphrase-stdin re-derive w/ fresh salt.
- FORK (surface to user): tier-1-env = (B) refuse+point-to-export/import [recommend default] vs (A) --print-new-key --i-understand forced swap.
- CLI: `junction vault rotate-key [--json] [--print-new-key --i-understand] [--new-passphrase-stdin]`. --json = {ok,tier,rotated,backupFile,newKey?} — NEVER plaintext/secretRef.
- Adversarial tests: kill between tmp-write/key-swap → opens under OLD; kill between rename/install → recovery restores; corrupt new file → verify catches; pre-existing undecryptable entry → abort; tier fidelity (no master.key written on env/keyring tier); concurrency lock; secret hygiene grep.

## 32.4 VAULT BACKUP/RECOVERY
- Backend-agnostic: export reads plaintext via live CredentialStore.get (works both backends — THE reason it's backend-agnostic).
- SCOPE (fork): credentials + their platforms [default] ; --include-profiles opt-in. platforms are secret-free config, needed as the credential FK.
- OAUTH2 = the big complexity: a cred holds FOUR refs (secretRef + oauthMeta.{refreshTokenRef,clientIdRef,clientSecretRef}, schema/credential.ts:41,47-48). Export must resolve ALL. addCredential REFUSES oauth2 (add-credential.ts:84) → import needs a DEDICATED oauth2 path: mint fresh refs, store.set each, repos.credentials.create, setOAuthTokens (repositories/credentials.ts:194).
- Archive format: [magic "JVLT"][ver u8][kdf u8][salt 16][iv 12][tag 16][ciphertext]. AAD=header bytes. key=deriveKeyFromPassphrase(pass, salt). plaintext=JSON.stringify(manifest). File 0600, tmp+rename.
- export: repos.credentials.list → resolve each ref via store.get (null→fail default / --skip-missing) → embed referenced platforms (+profiles if flag) → derive key → gcm-encrypt → write. Wipe plaintext buffers (buf.fill(0)) after.
- import: read+validate magic → passphrase (--passphrase-stdin headless) → gcmDecrypt (wrong pass/tamper → clean decrypt-failed, NOTHING written) → Zod-validate manifest → platforms upsert FIRST → creds (non-oauth via addCredential w/ NEW id+secretRef; oauth via dedicated path) → profiles last (remap cred-id refs).
- COLLISION (fork): --on-collision skip[default]|overwrite|error. overwrite caveat: removeCredential RESTRICT-fails for in-use creds.
- ATOMICITY: additive/resumable (per-cred fail-safe from add-credential.ts:166-178), NOT global all-or-nothing (no store+DB 2-phase). Re-run w/ skip resumes. FORK if strict wanted (temp-DB swap, heavier).
- CLI: `junction vault export --out <path> [--passphrase-stdin] [--include-profiles] [--skip-missing] [--json]` ; `junction vault import <path> [--passphrase-stdin] [--on-collision …] [--json]`. Export confirms passphrase twice interactively. Warn: archive is a BEARER SECRET.
- Adversarial: round-trip per-backend + cross-backend byte-identical (incl oauth2 4-refs); wrong pass → decrypt-failed nothing written; tamper header/ciphertext → tag fail; secret-never-on-disk (grep archive + run dir); no-leak (json/human/error.cause); missing-secret export fail; collision policies; partial-import resume.
