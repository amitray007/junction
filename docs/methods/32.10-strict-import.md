# 32.10 — strict all-or-nothing vault import

`junction vault import` is additive-resumable: a mid-import failure leaves earlier items committed. Add `--strict`: full pre-validation, then store writes with a whole-import compensation journal, then ONE synchronous SQLite transaction for all DB rows. Honest scope: **"strict" = DB-atomic + store-best-effort-compensated + full pre-validation** — NOT a two-phase commit across both stores (the keyring has no rollback primitive; same residual as 32.3 rotation documented).

**Proof-of-done:**
1. `junction vault import --strict <archive>`: any phase-1 failure (malformed cred incl. oauth2 candidate shape, kind-incompat, file-cap, unresolvable platform, ARCHIVE-INTERNAL duplicate credential/platform, profile-shape failure, or any collision under `--on-collision error`) aborts with ZERO writes (store AND DB — spy-proven).
2. A store.set or DB failure mid-import (flaky store / flaky repo decorator in tests) → EVERYTHING this import wrote (journaled rows AND refs) is removed again via reverse-order compensation, typed import-failed error. Tests assert the typed kind only (not constraint wording — must pass regardless of 32.9 integration order).
3. `--strict --on-collision overwrite` → typed refusal in core (mirrors the import-vault.ts:89-95 precedent), with a test.
4. Non-strict (default) behavior is byte-identical to today (the resume test at import-vault.test.ts:613 still passes unchanged). Strict happy path preserves verify-state exactly like non-strict (add a fixture that seeds lastVerifyResult and prove parity — NOTE non-strict itself drops oauth2 verify state today, a pre-existing bug filed separately; strict must REPLICATE it, not fix it one-sided).
5. The SIGKILL-mid-compensation residual (stranded rows/refs possible) + the phase1→2 TOCTOU are documented in the module header + a `docs/futures/gotchas.md` note is DRAFTED in the report (orchestrator lands register edits).
6. `pnpm verify` green.

## Design — COMPENSATION-BASED strict (doc-review decision; the tx design was proven unimplementable)
A one-transaction phase-3 design is NOT implementable without reimplementing addCredential/oauth internals (they interleave store+DB per credential — add-credential.ts:160-179, import-vault.ts:490-507 — and repos swallow errors into errAsync, unreadable inside a sync tx) — that drift is forbidden. Strict is therefore **prevalidate → run the EXISTING interleaved path under journaling decorators → compensate everything on any failure**:

- **Phase 1 — pre-validate, ZERO writes (strict-only).** The FULL checklist (anything missed here fails later AFTER secrets were written — violating the zero-writes promise):
  1. Build each candidate credential exactly as the real path does (manifest entries are `ManifestCredentialSchema` shapes, vault-manifest.ts:46-60 — the oauth2 check means constructing the candidate as `addOAuthImportedCredential` does) and `CredentialSchema.safeParse` it;
  2. kind↔platform compatibility (mirror add-credential.ts:95-101) + the 32KiB file-cred cap (:107-116) + `PlatformIdSchema` on every platform;
  3. **Archive-INTERNAL duplicates — hard error**: a Set over `(platformId, account)` (exact, untrimmed, case-sensitive — matching add-credential.ts:148) across the manifest; ditto duplicate platform ids (today they silently last-win via platformById, import-vault.ts:214-216). The 30.12 guard structurally CANNOT catch within-archive dups in strict (nothing commits between adds) — phase 1 is the only home for this check;
  4. Archive-vs-DB collisions via one `forPlatform` sweep (abort if `--on-collision error`);
  5. Profile shape (`ProfileSchema`) + the duplicate-toolNamespace guard (profiles.ts:140-149) + profile-name collisions.
- **Phase 2 — run the EXISTING import flow with journaling decorators.** Wrap `store` (journal every `set` ref) and the repo objects passed in (decorate `create`/`upsert`/profile-create with journaling — same structural pattern as the flakyStore test decorator, import-vault.test.ts:640-649; pass-through behavior identical). No reimplementation of any write path; verify-state carriage (setVerifyState after row-create, import-vault.ts:377-379) keeps working since the real path runs.
- **Phase 3 — on ANY failure: compensate in REVERSE order** — journaled profile rows → journaled credential/platform rows → journaled store refs (`cleanupRefs` + repo deletes; best-effort, same-process sync deletes; pre-existing rows are never journaled and never touched under skip/error). Return the typed import-failed error.
- **Honest wording (PoD #2/#3 accordingly)**: on failure "all rows/refs written by this import are removed again (best-effort compensation)" — NOT "zero DB rows committed"; the SIGKILL-mid-compensation residual can strand both DB rows and keyring refs (document). TOCTOU note: no lock is held between phases; a concurrent process inserting a colliding credential between phase 1 and 2 slips past prevalidation (32.9's unique index is the backstop; one line in the honest-limits note).
- **Overwrite under strict: REFUSE** (`--strict` + `--on-collision overwrite` → typed error in CORE, mirroring the existing refuse-a-combo precedent at import-vault.ts:89-95 with its test at import-vault.test.ts:116-130). Rationale: deleted refs are unrestorable on abort, and in-use collisions are only discoverable by ATTEMPTING the RESTRICT delete (a write). Test the refusal message.
- **CLI**: add `--strict` (boolean, default false) to importCommand; thread `strict` through ImportVaultInput; `--json` ok-summary gains `strict: true` (CLI is the only JSON consumer — verified). On abort, fold the compensation count into the import-failed `reason` string — do NOT extend the core error union (exhaustive formatters, outside `touches`).
- **Dropped-route case** (route referencing a credential absent from the archive, import-vault.ts:310-317): keep the silent drop, mirroring non-strict — state it in a comment.
- **Do NOT thread a raw `db` handle anywhere** — the compensation design needs none (openDbAndStore returns only {repos, store}, db.ts:45-60; getDatabase is uncached and a second call re-runs migrations — leave it alone).

## Tests
Extend import-vault.test.ts (mkdtemp + JUNCTION_HOME + seedPlatform + real export→import round-trips):
- strict + flaky store failing the Nth set → compensation removes ALL rows and refs this import wrote (spy on store.delete + DB read-back empty), typed import-failed.
- strict + a flaky REPO decorator failing the Nth create → same full compensation (the DB-failure leg).
- strict + malformed oauth2 candidate in manifest → phase-1 abort, store NEVER touched (spy: zero set calls).
- strict + ARCHIVE-INTERNAL duplicate (two manifest entries, same platform+account — hand-built manifest) → phase-1 abort; ditto duplicate platform ids.
- strict + collision + `--on-collision error` → phase-1 abort, zero writes.
- strict + `--on-collision overwrite` → typed refusal (message pinned).
- strict happy path → identical end-state to non-strict happy path (same rows, same refs, same verify-state — seed lastVerifyResult in the fixture).
- NON-strict: the existing resume test (~613) passes UNCHANGED.
- Dropped-route (route → credential absent from archive): silently dropped, same as non-strict.
