# Increment 32.6a — App-detail Connect CTAs for surfaceless apps

> First of the **32.6 "web dogfooding fixes"** batch (found 2026-07-07 by driving the real web UI).
> **The bug:** 44 of 45 catalog apps (everything except GitHub) render a near-empty `/app/:id` page with
> NO way to connect. **The fix is tiny** (~1 DTO field + 1 prop) and unblocks connecting to every catalog
> app. This is the highest leverage-to-effort item on the whole backlog.

## §0 — What / why (scope locked)

`/app/gitlab` (and 43 other apps) shows only "No connections to GitLab yet." with no Connect button.

**Root cause (verified):** only GitHub has an authored `surfaces[]`. For every other app,
`readAppDetail` (`data.server.ts:598-601`) hits the `entry.surfaces === undefined` branch and returns
`thinAppDetail(...)` → `surfaces: []`. The route then renders `EmptyAppState` with a **hardcoded
`authModes={[]}`** (`app.$id.tsx:883`), so the `authModes.length > 0` CTA block (Connect (OAuth) / Add
Credential buttons, `app.$id.tsx:191-213`) never renders. **The catalog entry's top-level `auth[]` is in
scope at the fallback but never plumbed into the thin DTO.**

**The fix:** carry the entry's `auth` modes through the thin DTO to `EmptyAppState`, mirroring the
existing surface-level path (`data.server.ts:648-655` does `surface.auth.map((a) => a.mode)` for
connected surfaces; we do the same at the app level: `entry.auth.map((a) => a.mode)`).

**Scope:** ONLY the surfaceless (thin) render path. The full surface-first view (available/connected
cards, tools) for the 44 apps is the separate **32.6c** (`surfaces[]` backfill) — NOT this slice. This
slice makes a surfaceless app *connectable* (the Connect (OAuth) / Add Credential buttons deep-link to
`/credentials`, exactly as they do today for the empty-GitHub case), which is the actual user-blocker.

## §0b — Load-bearing facts (verified against the real code)

- `EmptyAppState` (`app.$id.tsx:161-218`) already renders the full CTA block when `authModes.length > 0`:
  a chip per mode (`authModeLabel`), a primary **Connect (OAuth)** `<Link to="/credentials">` when
  `authModes.includes("oauth2")`, a secondary **Add Credential** link when `includes("token")||
  includes("byo")`. `"none"` → chip, no button. **No component change needed** beyond receiving real modes.
- `authModes` prop type is `("oauth2"|"token"|"byo"|"none")[]` — **exactly** `AppAuth["mode"][]`, so the
  map is a straight `entry.auth.map((a) => a.mode)`.
- `AppAuth` = `{mode:"oauth2";providerId}|{mode:"token"}|{mode:"byo"}|{mode:"none"}` (`catalog.ts:27-31`;
  zod `AppAuthSchema` `catalog-schema.ts:25-32`). `getCatalogEntry(id)` (`catalog/index.ts:31-33`) returns
  `AppCatalogEntry|undefined` and the entry **carries `auth: AppAuth[]`** (`catalog-schema.ts:227`).
- `data.server.ts` is "the ONLY file in @junction/web that imports @junction/core" and already imports
  `type AppAuth` + `getCatalogEntry` (lines 7,15) — no new import needed.
- The `AppDetail.app` DTO (`data.server.ts:555-559`) is `{id, displayName, iconSlug?, help?}` — **no
  `authModes` today**. That's the one field to add.

## §1 — Files & exact changes

**`packages/core`** — none. (Pure web DTO plumbing; the data already exists on the catalog entry.)

**`packages/web/src/server/data.server.ts`:**
1. Add `authModes: AppAuth["mode"][]` to the `AppDetail.app` DTO type (`:555-559`):
   ```ts
   export type AppDetail = {
     app: { id: string; displayName: string; iconSlug?: string; help?: AppHelp; authModes: AppAuth["mode"][] }
     surfaces: SurfaceView[]
     otherConnections: ConnectionMeta[]
   }
   ```
2. `thinAppDetail` (`:581-588`) takes the entry's auth modes and sets them:
   ```ts
   function thinAppDetail(
     id: string, displayName: string, authModes: AppAuth["mode"][], connections: ConnectionMeta[],
   ): AppDetail {
     return { app: { id, displayName, authModes }, surfaces: [], otherConnections: connections }
   }
   ```
3. At the fallback call site (`:598-601`), pass `entry?.auth.map((a) => a.mode) ?? []`:
   ```ts
   const entry = getCatalogEntry(id)
   if (entry === undefined || entry.surfaces === undefined || entry.surfaces.length === 0) {
     return thinAppDetail(id, entry?.displayName ?? id, entry?.auth.map((a) => a.mode) ?? [], connections)
   }
   ```
   (An unknown app id → `entry undefined` → `authModes: []` → the existing bare empty state. Correct: an
   app not in the catalog genuinely has no known auth.)
4. **The full (non-thin) path also builds `AppDetail`** (`readAppDetail` return, ~`:660-670`) — add
   `authModes: entry.auth.map((a) => a.mode)` to its `app` object too, so the type is satisfied AND a
   surface-authored app with zero connections still shows app-level CTAs consistently. (Confirm the exact
   return-object site and add the field.)

**`packages/web/src/routes/app.$id.tsx`:**
5. In `AppDetailPage`, the `app` from `useLoaderData()` now carries `authModes`. Change `:883`:
   ```tsx
   <EmptyAppState displayName={app.displayName} authModes={app.authModes} />
   ```
   (drop the hardcoded `[]`.)

**`packages/web/src/server/data.functions.ts`** — no change (it re-exports `AppDetail` by name;
the added field rides along).

## §2 — Design (I own this; follow the Geist system)

No new visual design — `EmptyAppState`'s CTA block already exists and matches the design system (the
same block renders today for a surfaceless GitHub). This slice just feeds it real data. The result: a
surfaceless app page shows the app's auth-mode chips + a **Connect (OAuth)** and/or **Add Credential**
button that deep-links to `/credentials` (the honest existing flow). No mockup needed — it's the
already-designed empty state, now populated.

## §3 — Tests (Vitest, happy-dom / Testing-Library — mirror the existing app.$id tests)

- **DTO:** `readAppDetail` for a surfaceless app (e.g. `gitlab`) returns `app.authModes` = `["oauth2",
  "token"]` (gitlab's catalog auth), `surfaces: []`. For an unknown id → `authModes: []`. For GitHub
  (surface-authored) → `app.authModes` populated too.

  Credential** links (assert both `<a href="/credentials">` CTAs present) — NOT just the bare "No
  connections yet" line. A `{mode:"none"}`-only app renders the chip but no button.
- Regression: a surface-authored app (GitHub) still renders its surface cards (this slice doesn't touch
  the `hasSurfaces` branch).
- The web leak-grep / metadata-only guards are unaffected (no secret in the DTO).
