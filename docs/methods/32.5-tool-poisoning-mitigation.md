# Increment 32.5 — Tool-poisoning mitigation

> Leaf slice of the 32.x wave, **fully independent** of the crypto foundation (touches `sources/proxy.ts`,
> not `credentials/*`). Mitigates the "tool poisoning" class: a malicious/compromised upstream MCP (or
> any source) returns a tool **description** stuffed with hidden instructions, invisible Unicode, or
> control characters aimed at steering the CALLING agent (prompt injection via tool metadata).

## §0 — What / why (scope locked — user-confirmed "sanitize + cap + surface")

junction is the chokepoint between upstream sources and the agent. Every tool description an agent sees
flows through **`createProfileProxy.listTools`** — specifically the point where a raw `ProviderTool` is
namespaced and pushed (`proxy.ts:183`, `namespaced.push({ ...t, name: nameResult.value })`). Today the
description passes through **verbatim**. This slice sanitizes it there, for **all source kinds** (the
proxy is source-agnostic — one enforcement point covers mcp/openapi/graphql/http/cli).

**Scope (proportionate to the single-user, operator-trust model):**
1. **NFKC normalize** the description (collapses compatibility/confusable Unicode forms).
2. **Strip control + format characters** — C0/C1 controls, and the invisible "format" class most abused
   for hidden-instruction smuggling (zero-width spaces/joiners, bidi overrides, etc.). **Via a CHAR-CODE
   LOOP, NOT a regex** (the `gotchas.md` Biome trap: `noControlCharactersInRegex` auto-fix MANGLES
   control-char ranges in a regex literal — `/[\x00-\x1f]/` gets silently rewritten to a printable range).
3. **Length cap** — truncate an over-long description to a fixed cap (defense against a megabyte-of-
   instructions description; a real tool description is short).
4. **Surface / audit on drift** — when sanitization actually CHANGES a description (or truncates it),
   record it so the operator can see a source is behaving oddly (the "surface" half of sanitize+cap+
   surface).

**DEFERRED (recorded in `revisit-when.md`): hash-pinning** (detecting that a previously-seen tool's
description/schema silently changed between calls — "rug pull" detection). It needs a persisted
per-tool baseline + a review UX; out of scope for this proportionate first pass. Sanitize+cap+surface is
the agreed scope.

## §0a — Load-bearing facts (verified against the real code)

- **The chokepoint is `proxy.ts` listTools**, the ONE place descriptions become agent-visible. `callTool`
  returns upstream `content` (the tool's RESULT), NOT descriptions — so sanitizing descriptions belongs
  purely in the list path. (We are NOT sanitizing tool result content this increment — that's a different,
  larger surface; descriptions are the tool-poisoning vector.)
- **`ProviderTool.description` is `string | undefined`** (`provider.ts:20`) — sanitize only when present.
- **The proxy is PURE core** — it does NOT receive an `AuditSink` today (audit is injected at the cli edge
  in `adaptToMcpHandlers`, per inc 31). So the drift-surface has a design choice (see §0b). We keep the
  **sanitize pure** and handle the **surface** without forcing an AuditSink into the pure proxy.
- **There are FIVE real `createProfileProxy` call sites (spec-flow C1 — the first draft undercounted):**
  `cli/commands/serve.ts:178`, `cli/commands/mcp.ts:178`, `web/src/server/probe.server.ts:87` (the three
  that must pass `onDescriptionDrift`), plus the tests. **`scoped-proxy.ts` (the keyed HTTP `/mcp`
  multi-profile layer) WRAPS an already-built `ProfileProxy` and passes `{ ...tool }` through
  (`scoped-proxy.ts:84`) — so sanitize at `proxy.ts:183` TRANSITIVELY covers the HTTP endpoint; no change
  there.** The sanitize is applied ONCE, below the scoped layer. A proof-of-done grep asserts no
  `createProfileProxy(` call site was missed.
- **The inc-31 `AuditEntry` schema is `event: "tool_call"` ONLY** (`audit/schema.ts:54`) — a
  description-drift event does not fit that shape (no tool_call happened). So the drift signal is NOT an
  `AuditEntry`; forcing it in would corrupt the tool-call audit's shape/consumers (`junction audit`
  filters assume tool_call). See §0b for the chosen surfacing mechanism.
- **Biome control-char gotcha is REAL and RECURRING** — the char-code loop is mandatory, and the file
  must be spot-checked after the PostToolUse `biome --write` hook runs (confirm the loop wasn't mangled;
  it can't be — it's not a regex — but confirm no regex crept in).

## §0b — How to "surface" drift (design resolved)

Two clean options; **choose the pure-return option (recommended)** to keep the proxy pure and avoid
polluting the tool_call audit:

**CHOSEN: sanitize returns a structured result; the drift SIGNAL rides out of the pure layer via the
existing pino LOGGER at the cli edge, NOT the AuditEntry schema.**
- `sanitizeDescription(raw) → { text: string; changed: boolean; truncated: boolean; strippedSuspicious:
  boolean }` is a **pure** function in a new `packages/core/src/sources/sanitize-description.ts`.
- **`strippedSuspicious` vs `changed` (spec-flow I2 — the noise fix):** `changed` is true for ANY diff,
  including cosmetic NFKC normalization / whitespace collapse (VERY common in legit non-English or
  multi-line descriptions). Surfacing drift on `changed` would emit a `warn` on nearly every `listTools`
  for many honest sources (`listTools` runs per agent tool-list refresh, connect-per-call), drowning the
  real signal. So sanitize ALSO returns **`strippedSuspicious`** = true ONLY when a control/format/
  invisible character was actually removed (the injection vectors — NOT NFKC-only, NOT whitespace-only).
- The proxy applies it at `proxy.ts:183`. To surface drift WITHOUT threading a sink into the pure proxy,
  add an **optional injected callback** to `createProfileProxy` — same injection pattern as
  `ResolveProviderFn`: `onDescriptionDrift?: (info: { namespace: string; tool: string; strippedSuspicious:
  boolean; truncated: boolean }) => void`, **fired ONLY when `strippedSuspicious || truncated`** (never for
  cosmetic-only changes). Pure core never imports a logger; the cli passes a thin callback that logs one
  structured `warn` line (via the same pino instance the audit sink uses, or `consola` for the CLI) —
  carrying ONLY metadata (namespace/tool/strippedSuspicious/truncated), NEVER the before/after text (which
  could itself carry injected content into the log). Absent callback → no-op (tests, and any caller that
  doesn't wire it).
- This keeps: proxy pure (callback injected, like resolveProvider), the tool_call audit schema
  untouched, and the drift observable to the operator (a `warn` log line when a source's description was
  sanitized). Records the "a source is doing something odd" signal without a schema change or a new
  persisted store.

(Rejected: adding a `description_sanitized` event to `AuditEntrySchema` — it widens the tool_call shape
and every `junction audit`/redact consumer for a non-tool-call event; heavier than warranted. Recorded
as a possible future if drift-tracking needs to be queryable.)

## §1 — The sanitizer (pure, char-code loop)

`packages/core/src/sources/sanitize-description.ts`:
```ts
// SPDX-License-Identifier: AGPL-3.0-only
// sanitizeDescription — neutralize prompt-injection vectors in an upstream tool description
// BEFORE it reaches the calling agent. NFKC normalize + strip control/format chars (char-code
// loop — NEVER a regex; Biome mangles control-char ranges, gotchas.md) + length cap.

/** Max description length surfaced to the agent. A real tool description is short; a longer one
 *  is either accidental bloat or a hidden-instruction payload. Truncated with an ellipsis marker. */
export const DESCRIPTION_MAX_CHARS = 2048   // tune with review; generous for legit tools, caps abuse

export interface SanitizedDescription { text: string; changed: boolean; truncated: boolean; strippedSuspicious: boolean }

export function sanitizeDescription(raw: string): SanitizedDescription {
  // 1) NFKC normalize (collapse compatibility/confusable forms).
  const normalized = raw.normalize("NFKC")
  // 2) Strip control + format chars via a CHAR-CODE LOOP (no regex — Biome gotcha).
  //    Remove: C0 (0x00–0x1F) INCLUDING \t \n \r (FROZEN DECISION — see note), DEL (0x7F),
  //    C1 (0x80–0x9F), and the invisible format class:
  //    ZWSP 200B, ZWNJ 200C, ZWJ 200D, LRM/RLM 200E/200F, bidi overrides 202A–202E,
  //    isolates 2066–2069, WORD JOINER 2060, BOM/ZWNBSP FEFF, and the interlinear/annotation
  //    anchors FFF9–FFFB.  strippedSuspicious flips true the moment ANY such char is removed.
  let out = ""
  let strippedSuspicious = false
  for (const ch of normalized) {            // iterate by code POINT (handles astral)
    const cp = ch.codePointAt(0) as number
    if (isStrippable(cp)) { strippedSuspicious = true; continue }
    out += ch
  }
  // 3) collapse ASCII whitespace runs (\t \n \r were stripped as controls above; only the space
  //    that remains + any Unicode spaces NFKC produced) → single space; trim. (Cosmetic — does NOT
  //    set strippedSuspicious.)
  out = collapseWhitespace(out)
  // 4) length cap — ASTRAL-SAFE truncation by code point (M4), never a mid-surrogate slice.
  const cps = Array.from(out)                // array of code points
  const truncated = cps.length > DESCRIPTION_MAX_CHARS
  const capped = truncated ? `${cps.slice(0, DESCRIPTION_MAX_CHARS - 1).join("")}…` : out
  return { text: capped, changed: capped !== raw, truncated, strippedSuspicious }
}
```
`isStrippable(cp)` is an explicit predicate (comparisons + a small Set of the named format code points),
NO regex. **FROZEN DECISION (spec-flow M3): strip `\n`/`\t`/`\r` as control chars** (a tool description is
prose; multi-line structure is exactly what an injection uses to fake a "SYSTEM:" block) — they count as
`strippedSuspicious`. Remaining spaces are collapsed cosmetically. `changed` compares against the ORIGINAL
raw (any diff); `strippedSuspicious` is the signal that gates drift surfacing.

## §2 — Wire into the proxy (`proxy.ts`)

- Add `onDescriptionDrift?` to the `createProfileProxy` signature (3rd param, optional — same injection
  spirit as `resolveProvider`). Threaded only into `listTools`.
- At `proxy.ts:183`, before push:
  ```ts
  let description = t.description
  if (description !== undefined) {
    const s = sanitizeDescription(description)
    description = s.text
    if ((s.strippedSuspicious || s.truncated) && onDescriptionDrift)
      onDescriptionDrift({ namespace: toolNamespace, tool: t.name, strippedSuspicious: s.strippedSuspicious, truncated: s.truncated })
  }
  namespaced.push({ ...t, name: nameResult.value, description })
  ```
- **`callTool` needs NO change** (descriptions aren't in the call path).
- **Update ALL FIVE real callers** (spec-flow C1) — the new param is optional, so a caller that omits it
  still gets sanitize (just no surfacing). Wire `onDescriptionDrift` at the three serving/probe sites:
  `cli/commands/serve.ts:178`, `cli/commands/mcp.ts:178`, `web/src/server/probe.server.ts:87` — each logs
  a structured `warn` (`{event:"description_sanitized", namespace, tool, strippedSuspicious, truncated}`)
  via the existing pino/consola. Metadata ONLY — never the description text. **`scoped-proxy.ts` needs NO
  change** — it wraps a `ProfileProxy` and inherits the already-sanitized descriptions (the HTTP `/mcp`
  endpoint is covered transitively).

## §3 — Tests

Core `sanitize-description.test.ts` (pure, exhaustive — the security core):
- Passthrough: an ordinary ASCII description → `changed:false`, identical text.
- **NFKC:** a fullwidth/compatibility variant normalizes; `changed:true`.
- **Control chars:** a description with `\x00`/`\x07`/`\x1b`/`\x7f` → stripped; `changed:true`. (Author
  the inputs with `String.fromCharCode`/`\u`, and confirm post-Biome-hook the TEST file's control chars
  survive — same gotcha; use ` ` escapes, not literal bytes.)
- **Invisible format chars:** ZWSP/ZWNJ/ZWJ/bidi-override/word-joiner/BOM each stripped; a
  "hello‮evil‬" bidi-injection → neutralized.
- **Whitespace:** a wall of `\n\n\n` collapses to single spaces; leading/trailing trimmed.
- **Length cap:** a `DESCRIPTION_MAX_CHARS + 500` description → truncated to the cap + ellipsis,
  `truncated:true`, `changed:true`.
- **Astral safety (preserve):** an emoji / astral code point in a short description is preserved (iterate
  by code point).
- **Astral safety (truncate, M4):** a description that hits the cap boundary mid-astral-pair truncates
  CLEANLY (no lone surrogate before the ellipsis) — assert the truncated string round-trips through
  `Array.from` without a replacement char.
- **`strippedSuspicious` gating (I2):** a control/format-char strip → `strippedSuspicious:true`; an
  NFKC-only change → `changed:true` but **`strippedSuspicious:false`**; a whitespace-only collapse →
  `changed:true`, `strippedSuspicious:false`. (Proves cosmetic changes don't trip the drift warn.)
- **Idempotent:** `sanitize(sanitize(x).text)` → `strippedSuspicious:false, truncated:false` (sanitizing
  clean output surfaces nothing).

Proxy `proxy.test.ts` additions (or a focused new test):
- A source returning a poisoned description → `listTools` returns the SANITIZED description; the raw
  control chars are ABSENT from the output.
- `onDescriptionDrift` fires once per SUSPICIOUS-or-truncated tool with the right metadata; does NOT fire
  for a clean description NOR for a cosmetic-only (NFKC/whitespace) change; the callback receives **no
  description text** (only namespace/tool/strippedSuspicious/truncated).
- Absent callback → no throw, sanitize still applied (all five call sites; a grep test asserts none was
  missed).

cli edge test: the drift callback emits exactly one structured `warn` with metadata only (grep the log
line — description text absent).
