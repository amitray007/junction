# Increment 30.9 — integrations.sh importer (dev-time catalog authoring accelerator)

> **Status:** planned (method file drafted 2026-07-06; awaiting doc-review + approval).
> Spec source: `docs/design/app-surface-model.md` §4 (esp. §4.2/§4.3/§4.4) +
> `docs/design/app-surface-model-roadmap.md` inc 30.9.
>
> **This increment builds a DEV-TIME script** that turns an `integrations.sh`
> `/api/{domain}/surface` payload into a **draft** junction catalog entry
> (`catalog.json` + `help.json` + `tools/*.tools.json`) for a human to review and
> commit. It is **NOT a runtime dependency** — integrations.sh is never called by
> the product; only by a maintainer authoring catalog entries. It writes files that
> validate against inc-30.8's `AppCatalogEntrySchema`.

---

## 0. TL;DR for the builder

Build `packages/core/scripts/import-from-integrations.mjs` (a `.mjs` **outside
`src/`**, like the shipped `gen-catalog.mjs` — so it may use `fetch`/`fs` without
tripping the core boundary guard). It:

1. **Fetches** `GET https://integrations.sh/api/{domain}/surface` (plain GET, no
   auth, deterministic cached JSON — verified 2026-07-06). NEVER `/discover` (that
   triggers their LLM). Fail loud on non-200 / non-JSON.
2. **Maps** the payload → a **draft** `catalog/{appId}/catalog.json` (+ `help.json`,
   + `tools/*.tools.json` if applicable), shaped to validate against
   **`AppCatalogEntrySchema`** (inc 30.8, `packages/core/src/apps/catalog-schema.ts`).
3. **Tags trust:** every mapped fact carries its `basis.via` (`detected` = machine-
   verified, `discovered` = LLM-guessed) into a review artifact, so the human knows
   what to scrutinize. `usedLlm:true` payloads are DRAFTS, never trusted truth.
4. **Writes to a REVIEW/STAGING location, NOT directly into the live catalog** — a
   maintainer diffs, edits, and moves it in. The importer never auto-commits.
5. **Re-runs `gen:catalog`-clean:** an imported+accepted entry must pass
   `AppCatalogEntrySchema.parse` and the inc-30.8 `catalog:check` (regenerate →
   git-clean) once a human moves it into `catalog/`.

**HARD CONSTRAINTS:** `core` runtime stays pure — the importer is a **dev/build
script only**, imported/run by no runtime code, adds NO runtime dependency
(integrations.sh is not a product dependency; if it vanishes, the shipped catalog
is unaffected). Never call `/discover`. Never auto-commit LLM-guessed data into the
live catalog. `pnpm verify` is THE gate. Match `gen-catalog.mjs`'s style.

## 1. Ground truth

### 1a. The TARGET — inc-30.8 `AppCatalogEntrySchema` (`packages/core/src/apps/catalog-schema.ts`, MERGED)
The importer emits files validating against this. Key shapes (verify against the file):
- **`AppCatalogEntry`**: `{ id, displayName, supportedKinds: PlatformKind[],
  auth: AppAuth[], aliases?, setupHints?, iconSlug?, surfaces?: AppSurface[], help?: AppHelp }`.
- **`AppAuth`** (discriminated on `mode`): `{oauth2,providerId} | {token} | {byo} | {none}`.
- **`AppSurface`**: `{ kind: PlatformKind, displayName, connection: AppSurfaceConnection,
  auth: AppAuth[].min(1), build: BuildRecipe, verify?: VerifyHint, docs?, agentGuidance?,
  starterTools?, notes? }`.
- **`AppSurfaceConnection`** (discriminated on `kind`): `mcp {transport, url?/command?, …}`
  (refined: http⇒url, stdio⇒command) · `openapi {specUrl, baseUrl?, maxTools?, select?,
  verifyOperationId?}` · `graphql {endpoint, defaultHeaders?}` · `http {baseUrl,
  defaultHeaders?}` · `cli {credentialEnvVar?}`.
- **`BuildRecipe`**: `{ platformIdTemplate, via: "flattened"|"descriptor", credential:
  {kind: CredentialKind, from:"auth"} }`. mcp/openapi/graphql ⇒ `flattened`; http/cli ⇒ `descriptor`.
- **`VerifyHint`** (on `kind`): `{openapi,operationId} | {mcp,listTools:true} |
  {graphql,typenameProbe:true} | {none}`.
- **`AppHelp`**: `{ category?, homepage?, statusPage?, description?, agentGuidance?,
  oauthApp?{registerUrl?,callbackPath?}, provenance?{authoredBy,researchedFrom?,lastReviewed?},
  install?{commands?,verifyCmd?,minVersion?}, authSetup?{interactive?,env?,configPath?}, notes? }`.

### 1b. The SOURCE — integrations.sh `/api/{domain}/surface` payload (verified live 2026-07-06)
Plain GET, no auth, deterministic cached JSON (200). Shape:
```
{ version, domain, detect{…}, summary, description, discoveredAt, usedLlm: true,
  credentials: { [credId]: { type: "bearer"|"jwt"|"oauth2"|"api_key", label,
                             generateUrl?, setup, acquisition? } },
  surfaces: [ { type: "graphql"|"cli"|"http"|"mcp",   // NOTE: NO "openapi" type
                url?, spec?, command?, packages?[{registryType,identifier,runtimeHint?}],
                transports?, slug, name, docs,
                basis: { via: "detected"|"discovered", evidence?[], signal?, verifiedAt? },
                auth: { status, entries: [ { use: [ { id, mechanics } ], basis } ] } } ] }
```
**Load-bearing source facts:**
- **`mechanics` is a tagged union on `source`** (`"http"` ⇒ `{in,headerName,scheme}` ·
  `"cli"` ⇒ `{command, env?[]}` · `"well-known"` ⇒ no extra fields). Branch on `source`.
- **`basis` is a tagged union on `via`**: `"discovered"` ⇒ `evidence[]` (source URLs);
  `"detected"` ⇒ `signal` + `verifiedAt` (machine-verified). This is the TRUST TIER.
- **integrations.sh has NO `openapi` surface type** — it emits REST as `type:"http"`
  with a `spec?` field sometimes present (GitHub's *graphql* surface had `spec`; the
  http surface did not). See §2c for the openapi-vs-http mapping rule.
- `credentials[].acquisition` and `.generateUrl` are OPTIONAL (Stripe omits them).
- `auth.entries[].use[]` is an array but every observed instance has exactly 1 entry.

### 1c. The generator contract (inc-30.8, `packages/core/scripts/gen-catalog.mjs`)
The importer's OUTPUT must be consumable by `gen-catalog.mjs`: per-app
`catalog/{id}/catalog.json` (+ optional `help.json` field-merged over inline `help`,
+ `tools/{kind}.tools.json` merged into that surface's `starterTools`). The orphan-
tools-file guard (30.8) means a `tools/{kind}.tools.json` MUST correspond to a
surface of that kind.

## 2. What the importer produces (the mapping — the core of this increment)

### 2a. App identity
- `id` = a slug derived from `domain` (`github.com` → `github`, `stripe.com` → `stripe`).
  **Human-confirmable** — the importer proposes; the reviewer can override (junction's
  id may differ from the domain, e.g. `google` not `google.com`). Reject fs-unsafe ids.
- `displayName` = a title-cased proposal from `name`/`domain` (reviewer edits).
- `supportedKinds` = the DISTINCT set of mapped surface kinds (see §2c).
- `iconSlug` = **not from integrations.sh** — leave undefined (the reviewer sets it
  from the `@thesvg/icons` set, as inc-30.5 established). Do NOT guess.

### 2b. Credentials → app-level `auth[]` + per-surface `auth[]`
Map each integrations.sh `credentials[credId].type` → junction `AppAuth.mode`:
| integrations.sh `type` | junction `AppAuth` |
|---|---|
| `oauth2` | `{ mode: "oauth2", providerId: <REVIEWER-SUPPLIED> }` ⚠️ |
| `bearer` / `api_key` / `jwt` | `{ mode: "token" }` |
| (nothing usable) | `{ mode: "byo" }` or `{ mode: "none" }` per reviewer |

⚠️ **`providerId` cannot be auto-derived** — it must reference a junction
`oauth/catalog.ts` OAuthProvider id (e.g. `github`, `google`). The importer emits a
**placeholder `"REVIEW:providerId"`** for oauth2 and flags it as a REQUIRED human
decision (a wrong providerId dead-links the connect CTA — the inc-30 reverse-coverage
guard depends on it). Do NOT ship a guessed providerId.
- The **app-level `auth[]`** = the union of all surfaces' mapped auth modes (dedup).
- Each **surface's `auth[]`** = the modes from that surface's `auth.entries[].use[].id`
  → the credential type → mode.

### 2c. Surfaces → `AppSurface[]` (the crux — kind mapping + the openapi/http rule)
integrations.sh `surfaces[].type` → junction `AppSurface.kind` + `connection`:

| integrations.sh `type` | junction `kind` | `connection` from |
|---|---|---|
| `mcp` | `mcp` | **branch on what the payload carries** (doc-review I5): a surface with a `url` → `{transport:"http", url, authHeader?}` (map bearer auth → `authHeader`); a surface with a `command`/`packages[]` and NO url → `{transport:"stdio", command}` (an npx/docker MCP server — the schema's stdio refine needs `command`). Do NOT write a degenerate `?"http":"http"` ternary. If neither url nor command is present → skip + flag for the reviewer. |
| `graphql` | `graphql` | `{endpoint: url}` |
| `cli` | `cli` | `{credentialEnvVar: <from cli mechanics env, MAPPED — see §2e>}` |
| `http` **+ has a usable OpenAPI spec** | `openapi` | `{specUrl: <spec/reviewer>, baseUrl: url}` |
| `http` **+ no spec** | `http` | `{baseUrl: url}` (empty — gap-filler; no starterTools) |

**The openapi-vs-http rule (§4.7 gap-filler):** integrations.sh emits REST as
`type:"http"` and does NOT reliably give a usable OpenAPI `specUrl`. So:
- If the reviewer can supply a real OpenAPI spec URL (from apis.guru top-up, or the
  provider's docs) → emit an **`openapi`** surface (schema-backed, auto tools).
- If no spec is available → emit an **`http`** surface, EMPTY (no starterTools), with
  a `notes[]` explaining it's the generic escape hatch.
- The importer **proposes `http` by default** (safe — never fabricates a spec URL) and
  **flags "openapi spec available? → upgrade this surface"** as a review action.
  **The importer NEVER invents a specUrl.**
- **`openapi` mapping is UNVERIFIED against live data** (no live payload had a
  `type:"openapi"`) — the mapping is spec-driven, reviewer-completed.

Per surface also set:
- `displayName` from `name` (reviewer edits).
- `build`: `{ platformIdTemplate: "{app}", via: kind∈{mcp,openapi,graphql}?"flattened":"descriptor",
  credential: { kind: <mapped>, from: "auth" } }`. Map credential `type`→`CredentialKind`:
  `oauth2`→`oauth2`, `bearer`/`jwt`→`bearer`, `api_key`→`api-key`.
- `verify`: `openapi`→`{kind:"openapi",operationId:"REVIEW:operationId"}` (reviewer
  supplies a param-less GET) · `mcp`→`{kind:"mcp",listTools:true}` · `graphql`→
  `{kind:"graphql",typenameProbe:true}` · `cli`/empty-http→`{kind:"none"}`.
- `docs` from `surfaces[].docs`.
- `agentGuidance`: leave undefined or a terse reviewer stub — do NOT LLM-generate.
- `notes[]`: record the `basis.via` + `evidence[]`/`signal` per surface so the trust
  tier is visible in-file (e.g. `"[discovered] evidence: docs.github.com/…"`).

### 2d. `help` (app-level, → `help.json`)
- `description` ← payload `description`. `provenance` ← `{ authoredBy: "junction",
  researchedFrom: ["integrations.sh", domain], lastReviewed: <REVIEW date> }`.
- `install` ← from cli surface `packages[]` (`registryType`→command: homebrew→
  `brew install <id>`, apt→`apt install <id>`, npm→`npm i -g <id>`, yum→`yum install
  <id>`) + `verifyCmd`/`minVersion` left for reviewer.
- `authSetup` ← from cli mechanics (`command`→`interactive`, `env[]`→`env`) + the
  credential `setup` prose is TOO LONG for a field — DON'T dump it; extract the URL/
  short hint or leave for reviewer.
- `oauthApp.registerUrl` ← a `credentials[oauth2].generateUrl` if present.
- Do NOT map `statusPage`/`category`/`homepage` from integrations.sh (not present);
  reviewer adds.

### 2e. `starterTools` — DO NOT auto-generate from integrations.sh
integrations.sh gives NO per-endpoint/per-command tool definitions. So the importer
emits **NO `tools/*.tools.json`** — starter tools are a reviewer/later concern
(§4.7). (An openapi surface gets its tools from the spec at connect time; an http
surface stays empty per the gap-filler rule.) This keeps the importer honest: it
never fabricates request-tools.

### 2f. The GH_PAT-class trap (reuse the 30.8 lesson — a CONVENTION, not a schema gate)
When mapping a cli surface's `credentialEnvVar` from integrations.sh `env[]` (e.g.
`GH_TOKEN`), transform a `*_TOKEN`/`*_SECRET`/`*_KEY`-suffixed name (e.g. `GH_TOKEN`
→ `GH_PAT`) and record the real→mapped mapping in `notes[]`.
- **IMPORTANT (a feasibility review corrected this):** the denylist is NOT enforced by
  the schema the importer writes to. `AppSurfaceConnectionSchema.cli`
  (`catalog-schema.ts:108-111`) is just `{kind:"cli", credentialEnvVar?: string.min(1)}`
  — **no denylist refine**; a raw `GH_TOKEN` WOULD pass `AppCatalogEntrySchema.parse`.
  The denylist lives on the *different* `CliConnectionSchema` (`cli-connection.ts:214`)
  and only bites LATER at connect time (30.11). So the transform is a **hand-applied
  convention matching the 30.8 precedent** (`catalog/github/catalog.json:72` + the note
  at `:84`), NOT something the parse gate catches.
- **Not algorithmic** (doc-review M4): the importer detects a denied suffix and emits a
  **`REVIEW:`-flagged suggested rename** (`GH_TOKEN` → suggest `GH_PAT`) in the review
  artifact — it does NOT auto-write a guessed rename into the load-bearing field. Matches
  the "never fabricate into a load-bearing field" ethos; the reviewer confirms the rename.

### 2g. Edge cases + no-fabrication rules (doc-reviews I4/I6/I7/M2)
- **Unknown domain / 404** (I7): distinguish a 404 ("integrations.sh has no surface for
  `{domain}` — author from scratch"; actionable message, clean non-zero exit) from a
  5xx/network error ("service problem — retry"). A 404 is EXPECTED for many apps, not a bug.
- **Zero mappable surfaces** (I6): still emit the identity + auth + help draft, but flag
  prominently in the review artifact "no surfaces mapped — author surfaces manually."
  (An empty `supportedKinds:[]` is schema-valid but semantically dead — don't ship it silently.)
- **Unknown surface `type`** (I6): integrations.sh could add a `type` junction doesn't
  support → **skip it + record a `REVIEW:` note** ("unrecognized surface type `<x>`");
  NEVER invent a junction kind for it.
- **`use.length > 1` (AND-composed auth)** (I4): junction's `AppAuth[]` is a DISJUNCTION
  of accepted modes, not a conjunction. On >1 `use[]` entry, do NOT silently drop the
  extras — map each to a mode, dedup, AND flag "AND-composed auth: N creds required;
  junction models accepted modes as a disjunction — reviewer must confirm."
- **oauth2 dedup by `(mode, providerId)`, not `mode`** (M2): github ships TWO oauth2
  providers (`github`, `github-app`). Dedup on `mode` alone collapses them. Since both
  get a `REVIEW:providerId` placeholder, keep BOTH distinct entries and flag "N oauth2
  credentials — assign distinct providerIds." Do NOT lose a provider to dedup.

## 3. Trust tagging, the review artifact, staging + collision (§4.3)

### 3a. The review artifact — a MACHINE-CHECKABLE JSON sidecar (doc-review I2)
Emit **`_import-review.json`** (NOT "or console report" — a test must parse it) next
to the draft, with a defined shape:
```json
{ "app": "github", "domain": "github.com", "usedLlm": true,
  "facts": [ { "path": "surfaces[0].connection.endpoint", "via": "discovered",
               "evidence": ["https://docs.github.com/…"] }, … ],
  "placeholders": [ { "path": "surfaces[0].auth[0].providerId", "token": "REVIEW:providerId",
                      "reason": "oauth2 providerId must reference an oauth/catalog.ts provider" }, … ],
  "counts": { "detected": 0, "discovered": 12, "placeholders": 3 },
  "collision": { "exists": true, "hasSurfaces": false, "hasHelpJson": true } }
```
Optionally ALSO render a human `.md` from it — but the `.json` is the testable artifact.

### 3b. The `REVIEW:` sentinel contract (doc-review I3)
A field the reviewer MUST resolve carries the exact string prefix **`REVIEW:`** (e.g.
`"REVIEW:providerId"`, `"REVIEW:operationId"`). Placeholders the importer emits:
oauth2 `providerId`, openapi `verifyOperationId`, `iconSlug` (omit — leave undefined,
not a placeholder), install `verifyCmd`/`minVersion`.
- **A raw draft with `REVIEW:` tokens is INTENTIONALLY schema-invalid until filled** —
  that's the point: `gen:catalog` fails loud if an un-filled draft is committed. So the
  §4 "validates against `AppCatalogEntrySchema`" check runs AFTER a test fills the
  placeholders with known-good values.
- **The importer must NEVER emit an `openapi` surface with a placeholder `specUrl`** —
  `specUrl` is `z.string().url()` (required), so a `REVIEW:` token there can't even be a
  URL. This is WHY §2c defaults REST → `http` (no specUrl needed): a placeholder never
  reaches a required-URL field.

### 3c. Collision policy — the app ALREADY EXISTS (doc-review C2, load-bearing)
**The 30.8 migration created ALL 45 app dirs** (github, stripe, google, … all exist).
So the importer ALWAYS collides. Rules:
- **The importer NEVER writes into `packages/core/src/apps/catalog/{id}/`.** It writes
  only to a staging dir (§3d). No exceptions — it cannot clobber a hand-authored entry.
- **Detect + report the collision** in `_import-review.json` (`collision.exists`,
  `.hasSurfaces`, `.hasHelpJson`): "app `{id}` already exists in the live catalog;
  this draft is a RE-DRAFT for the reviewer to 3-way-merge by hand — do NOT overwrite
  the authored `help.json`/`surfaces[]`."
- **github specifically** is already fully hand-authored (5 surfaces) — the importer's
  draft is a *comparison reference* (§4), never a replacement.
- **stripe specifically** exists as a THIN entry (no surfaces, no help.json) — the
  importer's draft ADDS surfaces the reviewer can adopt; still staging-only.

### 3d. Staging dir (doc-review I1)
- **Exact path (a contract, not "e.g."):** `packages/core/scripts/.import-staging/{id}/`.
- **Add `packages/core/scripts/.import-staging/` to `.gitignore`** (and say so here) —
  staging output must NOT be committed or trip `catalog:check`/CI `git diff --exit-code`.
- **Idempotent re-run:** wipe `.import-staging/{id}/` before writing (no stale files).

### 3e. Invariants (unchanged intent)
- **Never auto-accepts `discovered` data as final** — it's a draft.
- The **runtime safety net still applies** (recorded, not built here): even after a
  human commits an entry, junction's inc-28.9 **verify-on-add** tests the credential
  against the real upstream at connect time (30.11) — a wrong guess fails there too.

## 5. Explicitly OUT of scope

> **⚠️ Scope decision (orchestrator, 2026-07-06 — resolves a design-doc
> contradiction a doc-review caught).** Both design docs (`app-surface-model.md`
> §8, `-roadmap.md` inc 30.9) listed **apis.guru spec-URL top-up + the Nango
> license review** as 30.9 line items. **DECISION: split those into a separate
> follow-up (inc 30.9.5), NOT 30.9.** Rationale (architecture over expedience): the
> integrations.sh→draft mapping is the core, self-contained value; apis.guru
> top-up adds live OpenAPI-spec fetching + parsing + matching (a materially larger
> surface), and the Nango review is a legal gate that shouldn't block the mapping
> work. A focused 30.9 ships sooner and cleaner; 30.9.5 does the spec-URL enrichment
> on top. **The two design docs are updated to match this split** (no silent
> divergence). So for 30.9, an `http` REST surface with a `REVIEW:specUrl`-free
> default (§2c) is the CORRECT output — the reviewer or 30.9.5 supplies specUrls.

- Auto-committing into the live catalog (human review gate is mandatory — §3).
- Generating `starterTools` (§2e — integrations.sh has none; never fabricate).
- **apis.guru spec-URL top-up + the Nango `providers.yaml` license review → inc
  30.9.5** (the scope decision above). 30.9 defaults REST → an `http` surface and
  never fabricates a specUrl; upgrading http→openapi with a real spec is 30.9.5 /
  reviewer work.
- The `/discover` LLM endpoint (banned — deterministic `/surface` only).
- Bulk-importing all 45 apps (this increment proves the importer on github + stripe;
  bulk authoring is a separate, human-paced effort).
- The connect flow / verify-on-add execution (30.11).
