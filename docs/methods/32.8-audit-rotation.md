# 32.8 — Audit-log rotation / retention

`<home>/audit.log` grows unbounded (BACKLOG §1d). Fix: **size-based rotation at serve/mcp-serve startup**, manual rename, no new dependency. Rotating BEFORE the sink's fd opens sidesteps the rename-under-open-writer hazard entirely (an open SonicBoom keeps writing to the renamed inode; we never rename under a writer).

**Proof-of-done:**
1. Starting `junction serve` or `junction mcp serve` with `audit.log` ≥ the max size rotates it: `audit.log → audit.log.1`, shifting `.1→.2 … ` up to `keep`, deleting beyond; a fresh `audit.log` is then created by the sink with mode 0o600; rotated files keep 0o600.
2. Under-sized or missing `audit.log` → no-op (`skipped`). A rotation failure NEVER blocks serve startup — the outcome is a returned discriminated value; the call site warns in its own idiom (stderr on mcp).
3. Readers stay on the current file only (decision: `junction audit` + web `/audit` read `audit.log`; `.1..K` are on-disk history for manual inspection) — document this in the rotate module header.
4. Unit tests for rotate logic (tmpdir fixtures); `pnpm verify` green.

## Changes
1. **New `packages/core/src/audit/rotate.ts`** — `export async function rotateAuditLogIfOversized(auditLogFile: string, opts?: { maxBytes?: number; keep?: number }): Promise<RotateOutcome>` where `RotateOutcome = { kind: "rotated" } | { kind: "skipped" } | { kind: "failed"; code: string }` (discriminated outcome — the CALLER logs in its own idiom; rotate.ts does NOT log, keeping it decoupled from the logger seam). Defaults: `maxBytes = 8 * 1024 * 1024`, `keep = 5`. Logic: `stat` (ENOENT → skipped); if `size < maxBytes` → skipped; else from `keep-1` down to 1 rename `audit.log.N → audit.log.N+1` (ignore ENOENT per step), rename `audit.log → audit.log.1`, unlink anything beyond `.keep`. **Async `node:fs/promises` only — no `*Sync`** (boundary guard). Any unexpected failure → `{ kind: "failed", code }` (fs error code only — never a message that could embed content). Header comment must state: (a) the rotate-before-open design rationale; (b) readers stay on the current file only (post-rotation, `junction audit` honestly shows "no entries yet" while history sits in `.1` — deliberate); (c) rotation is safe against the rotating process's own sink, but a concurrently RUNNING server keeps appending to the rotated generation (renamed inode) until it restarts — no corruption, its lines just live in `.1`; across repeated rotations that open generation can eventually be unlinked while open (accepted for a single-user tool); (d) two processes rotating simultaneously interleave harmlessly (each step is one atomic rename that either wins or ENOENTs — worst case the oldest file is deleted one rotation early), which is why there's no lockfile. **Export from `packages/core/src/index.ts`** alongside the existing `./audit/read.js` exports — there is NO `audit/index.ts` barrel; do not create one.
2. **Call sites** — in `serve.ts` and `mcp.ts` (the named-profile path, after `getPaths()`), immediately BEFORE `createFileAuditSink(paths)`: `const rotate = await rotateAuditLogIfOversized(paths.auditLogFile)` then on `kind === "failed"` warn in the file's OWN existing idiom (serve.ts: its consola-style warn; mcp.ts: `process.stderr.write` — stdout carries the MCP protocol). Keep `createFileAuditSink` itself sync/unchanged. The mcp.ts synthetic-default early-return path creates no sink and needs no rotation.
3. **Stale-comment sweep** (code comments, not docs registers — the builder DOES update these): `packages/core/src/audit/read.ts:~120` ("full rotation deferred"), `packages/web/src/server/audit.server.ts:13-15,25` (same), `packages/core/src/paths/index.ts:19-21` ("rotation/retention deferred") → reference the shipped rotation + the readers-current-file-only decision.
4. **Tests — `packages/core/src/audit/rotate.test.ts`** (mirror read.test.ts mkdtemp style): oversized file → rotated to `.1` with the old content, current gone (until a writer recreates), `.1` mode 0o600; shift chain: existing `.1` becomes `.2`; `keep` bound: a `.5` present before rotation is deleted (with keep=5 nothing beyond `.5` survives — craft with small keep like 2 for clarity); under-sized → untouched, returns false; missing → false, no throw; rotation into a read-only dir → false, no throw (best-effort proof). Use tiny maxBytes overrides (e.g. 10 bytes) in fixtures.

## Hard invariants
- Never rename while a sink in THIS process has the file open (call before sink construction only).
- 0o600 preserved on every file the rotation leaves behind; never create a file yourself (rename preserves perms; the fresh file is the sink's job with its `mode: 0o600`).
- No sync fs; no new deps; rotation failure never propagates.
- Audit content is metadata-only already — do not log any entry contents in warns.
