# Increment 30.13 — Curated catalog expansion

> **Reframe (user, 2026-07-10):** don't mechanically backfill all 35 thin apps — **curate the TOP 3-4
> integrations per category** and add the specific high-value platforms the user named. An app nobody
> uses isn't worth a surface. This mixes **surface-authoring existing thin apps** (the 32.6c flow) with
> **net-new app entries** (some needing new OAuth providers). **Every connection value below was
> live-verified + cited** by the research pass (2026-07-10); the no-fabrication rule is absolute.

## §0 — What / why (scope locked)

Two work types:
1. **Surface existing thin apps** — add `surfaces[]` to a catalog entry (provider usually already exists).
2. **Add net-new app entries** — a new `catalog/<id>/catalog.json` (+ regen); an **oauth2** one also needs
   a matching OAuth provider in `oauth/catalog.ts` that **must land in the same commit** (a bidirectional
   coverage test in `catalog.test.ts` fails otherwise).

Also: **establish the `category` taxonomy** — the schema has `category: z.array(z.string()).optional()`
(`catalog-schema.ts:172`) but NO app uses it yet. This increment sets it on every touched app.

**Category taxonomy (7):** `Productivity` · `Communication` · `Developer` · `CRM` · `Observability` ·
`Search` · `Social`.

## §0a — Load-bearing facts (research-verified 2026-07-10)

- **Net-new app checklist:** create `catalog/<id>/catalog.json` (`id` MUST equal the dir name, slug
  `^[a-z0-9][a-z0-9-]*$`; required `id`/`displayName`/`supportedKinds`/`auth`); author `surfaces[]`; if any
  `auth` is `{mode:"oauth2",providerId:X}`, add provider `X` to `oauth/catalog.ts` **in the same commit**;
  optional `iconSlug` MUST resolve to a `@thesvg/icons` module (else `gen-brand-icons.mjs` throws — omit
  it → letter-tile fallback). Then `pnpm --filter @junction/core build && gen:catalog` (+ `gen:icons` if
  icons changed) and commit the regenerated `catalog.generated.ts`. `catalog:check` (in `quality`) enforces regen.
- **Build recipe** (`BuildRecipeSchema`): `{platformIdTemplate:"{app}-{kind}", via:("flattened" for
  mcp/openapi/graphql | "descriptor" for http/cli), credential:{kind, from:"auth"}}`.
- **openapi >10 MiB cap** (`SPEC_BYTE_CAP = 10,485,760`, fires mid-fetch before `select`): every openapi
  spec below was byte-measured and is UNDER cap. A future >10 MiB spec must author mcp/http instead.
- **`tokenEnvVar` (stdio MCP) has NO `*_TOKEN` suffix guard** (verified — only the runtime env-*map* keys
  are denylisted, not the token var name). So `GOALERT_TOKEN`/`SONARQUBE_TOKEN` are fine. (The `cli`
  `credentialEnvVar` DOES reject `_TOKEN`/`_SECRET`/`_KEY` → use `_PAT`.)
- **First-of-kind paths (never exercised in the committed catalog — QA them against real connect):**
  **stdio-transport MCP surfaces** (`connection:{kind:"mcp",transport:"stdio",command,args,tokenEnvVar?}`)
  for Shopify Dev MCP / SonarQube / GoAlert; openapi `maxTools`/`select` if used.
- **Self-hosted / per-instance surfaces have NO fixed catalog URL** (GoAlert, SonarQube Server, InfluxDB
  OSS, Outline self-hosted) → author the fixed-host variant (SonarCloud, InfluxDB Cloud is per-region so
  omit) or the cli/stdio surface where the base URL is operator-supplied at connect time.

## §3 — Build shape (waves, after approval)
A worktree wave, batched by independence (all disjoint `catalog/<id>/` dirs + a shared `catalog.generated.ts`
regen at integration + `oauth/catalog.ts` only if providers included):
- **Wave batch by category** (3-4 builders), each authoring its apps from THIS file's verified values +
  citing the source per surface. The one shared file is `catalog.generated.ts` (regenerated once at serial
  integration, not per-worktree — mirrors 32.6c). `oauth/catalog.ts` (if providers) is a single-writer slice.
- Each builder: author `catalog.json` (+ `category`) → `build && gen:catalog` locally to self-validate →
  do NOT commit the regenerated file from the worktree (regen once at integration to avoid conflicts on the
  generated snapshot) — OR each commits its own regen and integration takes the final regen. **Decide the
  generated-file strategy at build time** (recommend: builders author only the source `catalog.json`; the
  orchestrator runs ONE `gen:catalog` at integration + commits the single regenerated snapshot).
