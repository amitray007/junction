# Increment 32.1 — CI security tooling (quick wins) + serve dir-perms

> First slice of the inc-32 security-hardening decomposition (32.1 CI quick-wins → 32.3 master-key
> rotation ∥ 32.4 vault backup ∥ 32.5 tool-poisoning). Lands FIRST, alone — low product risk, and
> type-coverage becomes the regression net that guards the credential-critical slices behind it.

## §0 — What / why (scope locked)

Three low-effort, low-risk CI hardening additions + one trivial serve-path fix. NO product/credential
behavior change. Each is mostly-green-immediately (the codebase already complies), so this slice
LOCKS existing invariants rather than fixing violations.

1. **type-coverage ≥99% gate** — fails CI if `any` creeps into a credential broker. Spec §5b/§71.
2. **SPDX header CI gate** (`fsfe/reuse-action` OR a lightweight grep gate) — every source file already
   carries `SPDX-License-Identifier`; the gate locks it. `revisit-when.md:29`.
3. **osv-scanner** — dependency CVE scan (complements the existing non-blocking `pnpm audit`). Low risk.
4. **`ensureHome()` on serve entrypoints** — `junction serve`/`mcp serve` never call `ensureHome()`
   (only `init` does), so a serve-first home's DIR can be 0755 (`getDatabase` mkdir has no mode). The
   inc-31 audit-log leak was closed at the FILE level (0o600); this closes the DIR level too
   (defense-in-depth). `revisit-when.md:27`, `gotchas.md:7`.

**Dropped from scope** (research): trufflehog (redundant with the existing gitleaks); knip + semgrep +
CodeQL (→ deferred 32.2, noisy/heavier).

## §0b — Load-bearing facts (measured, not assumed)

- **type-coverage is NOT installed** (verified). **The true SOURCE-only aggregate (dist + tests
  excluded) is 99.85%** — measured by the doc-review with a proper include-all config. openapi-client
  source-only is **99.77%** (NOT 98.85 — the earlier per-package numbers were inflated by scanning
  built `dist/*.d.ts` that the packages import). **So the ≥99% gate PASSES TODAY with NO source
  change.** The `base-url.ts` any-fix is OPTIONAL cleanup, NOT a prerequisite — do NOT put it on the
  critical path (and NEVER weaken a type to pass; nothing needs weakening). Measure-then-set the
  threshold at 99.
- **type-coverage does NOT follow project references** (doc-review confirmed: root tsconfig →
  `0/0` false-success; no `--project`-refs mode fixes it). Need a dedicated
  **`tsconfig.typecoverage.json`** with an EXPLICIT include. **The glob MUST cover the nested + web
  packages** — a bare `packages/*/src/**/*.ts` silently DROPS `mcp/server`, `mcp/client`, and all of
  web, shrinking what the gate guards. Use:
  `["packages/*/src/**/*.ts", "packages/mcp/*/src/**/*.ts", "packages/web/src/**/*.tsx"]`, exclude
  `**/*.test.ts`/`**/dist/**`. (web is also absent from the root tsconfig references — the include-all
  config is the only way to get it into the number.) This gave the full 66,794-symbol / 99.85% aggregate.
- **SPDX gate is NOT green on the current tree** (doc-review — `dist`/`dist-tsc` are gitignored + NOT
  tracked, so they can't be the "missing" ones; the earlier 262/275 was miscounted). Exactly **ONE
  tracked non-dist source file lacks the header: `packages/core/tsdown.config.ts`** (the other 8
  `tsdown.config.ts` all have it). **The builder MUST add that header** as part of this increment, or
  the bash gate is born RED. A bash grep-gate over tracked non-dist `*.ts`/`*.tsx` (mirroring
  `no-publish-guard` in `security.yml:31-44`) is the recommended approach (zero new config).
- **`ensureHome()` (`core/paths/index.ts:65`)** is a `ResultAsync<JunctionPaths, PathsError>` that
  `mkdir`s the home 0700. Called only at `init.ts:36`. `serve.ts`/`mcp.ts` open the DB (via
  `getDatabase` → mkdir no-mode → 0755) without it.

## §1 — Proof-of-done

  if a package genuinely can't hit 99% without unsafe changes, set the gate at the honest measured
  floor + record why, NEVER weaken a type to pass).

  (`packages/core/tsdown.config.ts`) and would FAIL if a new source file omits the header.

  matching the gitleaks posture).

  Proven: `rm -rf /tmp/h && JUNCTION_HOME=/tmp/h junction mcp serve …` → `stat /tmp/h` shows 0700.
- `pnpm verify` green; the new CI jobs green on this branch.

## §2 — Plan (single slice — mostly CI YAML + one small source fix)

1. **type-coverage:** `pnpm add -D -w type-coverage`. Add `tsconfig.typecoverage.json` with the
   include globs from §0b (covering mcp/* + web .tsx — NOT a bare `packages/*/src`). Add
   `type-coverage` + `type-coverage:check` (`type-coverage -p tsconfig.typecoverage.json --strict
   --at-least 99`) scripts. Wire a CI job in **`security.yml`** (doc-review: cleaner than ci.yml's
   bundled quality job). **No source fix needed — the gate passes at 99.85% today.** (OPTIONAL: the
   `openapi-client` implicit-anys in `base-url.ts`/`http.ts`/`parse.ts`/`tools.ts` are index-access
   widening from `Array.isArray` on `unknown`; a local `unknown[]` annotation tightens them — cleanup
   only, not required, do NOT gate on it.)
2. **SPDX gate (bash, recommended):** FIRST add the missing header to `packages/core/tsdown.config.ts`
   (else the gate is born red — doc-review F4). Then add a `security.yml` bash job: `git ls-files
   '*.ts' '*.tsx'` filtered to non-dist, grep each for `SPDX-License-Identifier`, fail listing any
   missing. Mirror the `no-publish-guard` bash-gate idiom (`security.yml:31-44`). (Defer full
   `fsfe/reuse-action`/`REUSE.toml` unless REUSE compliance is separately wanted.)
3. **osv-scanner:** add a `security.yml` job — `google/osv-scanner-action` (pinned to a commit SHA per
   the repo convention; it natively parses `pnpm-lock.yaml` at the repo root); fail on high/critical.
   Leave the existing `(pnpm audit --audit-level=high || true)` in the `quality` npm SCRIPT untouched
   (it's in `package.json`, not a workflow line — don't hunt for a workflow step to preserve).
4. **ensureHome on serve:**
   - `serve.ts`: insert `await ensureHome()` (with `.isErr()` handling mirroring the existing
     `dbResult` guard ~:86) BETWEEN `getPaths()` (~:63) and `getDatabase` (~:86). Fail clean on err.
   - `mcp.ts`: this file has a `!profileName` EARLY-RETURN before any DB (`~:98`, the synthetic-default
     branch) — place `ensureHome()` at the **TOP of `run()` before that check** so ANY `mcp serve`
     creates a 0700 home (the proof-of-done exercises the named path; top placement covers both).
     **Use `process.stderr.write` for the error path, NOT `consola`** (`mcp.ts:6-7` stdout-purity — the
     stdio MCP channel must stay clean; unlike serve.ts which may use consola).
   - Add a test asserting the served home dir is 0700 (mirror the inc-31 audit-perms test shape).

**No wave** — this is one small serial slice (CI config + a 6-site type fix + a 2-line serve fix).
Delegate to ONE Sonnet builder.
