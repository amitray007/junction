# 41.1 — CLI Full Access: core schema + extracted-schema type + storage

**Builder: Sonnet.** Self-contained. Design source of truth: `docs/specs/2026-07-16-cli-exploratory-mode.md` (read §3 constraints + §5 Fable decisions first). This is the **blocking core slice** — 41.2/41.3/41.4/41.5 all depend on it. It must land alone, `pnpm verify` green, before the others fan out.

## What / why

Today `CliConnectionSchema` (`packages/core/src/schema/cli-connection.ts`) is `{ tools: CliTool[] (min 1), credentialEnvVar? }` — a CLI platform IS its fixed tool list. We add a **second mode**: **Full CLI access**, where the platform is a single pinned binary the agent drives freely, plus a persisted **extracted command schema** (from recursive `--help`), plus optional named **shortcuts** (the old declared tools, demoted to sugar).

This slice adds ONLY the data types + storage + validation. No provider, no extractor, no UI — those are later slices. Nothing about existing declared-mode behavior may change (strict back-compat).

## Interfaces to produce (the seam others build against)

### 1. `CliConnection` becomes mode-tagged (back-compat!)

In `packages/core/src/schema/cli-connection.ts`, refactor `CliConnectionSchema` so it accepts BOTH:

- **declared (legacy, default):** existing shape `{ tools: CliTool[] (min 1), credentialEnvVar? }`. Stored rows have NO `mode` field today — they MUST still parse. Do this by making `mode` optional with `.default("declared")` OR a `z.union` with a `.catch`/preprocess that treats a missing `mode` as `"declared"`. **Verify against a real legacy fixture** (a `{tools:[...],credentialEnvVar:"GH_PAT"}` object with no `mode`) that it still parses to a declared connection.

- **full-access (new):**
  ```ts
  {
    mode: "full-access",
    binaryPath: string,          // absolute realpath, literal, metachar-clean (reuse the argv[0] guards)
    credentialEnvVar?: string,   // same denylist rules as today
    policy: CliPolicy,           // ONE platform-level policy (not per-tool)
    schema: ExtractedCliSchema,  // the persisted --help tree (type below)
    shortcuts?: CliTool[],       // optional named saved commands (reuse CliToolSchema verbatim)
  }
  ```
  Reuse the existing `binaryPath` guards that `CliToolSchema` applies to argv[0]: must start with `/`, must pass `hasUnsafePathChars`. Reuse `CliPolicySchema` for `policy`. Reuse `CliToolSchema` for each `shortcuts` entry. `credentialEnvVar` reuses the identical denylist refine (factor the refine predicate into a shared helper if that avoids duplication, but do NOT over-abstract — a duplicated 3-line refine is fine per the rule-of-three).

Recommended concrete shape: a discriminated union is cleanest, but the missing-`mode` back-compat is the trap. Preferred implementation:
```ts
const DeclaredCliConnection = z.object({ mode: z.literal("declared").optional().default("declared"), tools: z.array(CliToolSchema).min(1), credentialEnvVar: ... })
const FullAccessCliConnection = z.object({ mode: z.literal("full-access"), binaryPath: ..., credentialEnvVar: ..., policy: CliPolicySchema, schema: ExtractedCliSchemaSchema, shortcuts: z.array(CliToolSchema).optional() })
export const CliConnectionSchema = z.union([FullAccessCliConnection, DeclaredCliConnection]).<...back-compat...>
```
Order the union so a legacy object (no `mode`) lands in `DeclaredCliConnection`. Add tests proving: (a) legacy no-`mode` object → declared; (b) `mode:"declared"` explicit → declared; (c) valid full-access object → full-access; (d) full-access with a bad binaryPath (relative / metachars) → rejected; (e) full-access with a denylisted credentialEnvVar → rejected.

Export a discriminant helper: `export function isFullAccess(c: CliConnection): c is FullAccessCliConnection`.

### 2. `ExtractedCliSchema` — the persisted --help tree

New file `packages/core/src/schema/cli-schema.ts` (single purpose). Per Fable Q5 (one shape always, never drop a node) and Q2 (node shape):

```ts
export const CliFlagSchema = z.object({
  name: z.string(),                 // "--title"
  alias: z.string().optional(),     // "-t"
  takesValue: z.boolean(),
  description: z.string().optional(),
})

export const CliSchemaNodeSchema: z.ZodType<CliSchemaNode> = z.lazy(() => z.object({
  path: z.array(z.string()),        // ["pr","create"]; [] = root
  parsed: z.boolean(),              // false → generic parser failed on THIS node
  explored: z.boolean(),            // false → ceiling/lazy: not yet probed (Fable Q4)
  description: z.string().optional(),
  usage: z.string().optional(),
  flags: z.array(CliFlagSchema).default([]),
  positionals: z.array(z.object({ name: z.string(), description: z.string().optional() })).default([]),
  subcommands: z.array(CliSchemaNodeSchema).default([]),  // FULL nodes on disk; the help TOOL returns only names+summaries (that projection lives in 41.3, not here)
  rawHelp: z.string().optional(),   // always stored; the tool returns it only when parsed:false
  helpHash: z.string().optional(),  // normalized-help hash for loop detection (Fable Q4)
}))
```
Add a top wrapper `ExtractedCliSchemaSchema = z.object({ binaryName: z.string(), extractedAt: z.string(), root: CliSchemaNodeSchema, truncated: z.boolean() })` (`truncated` = a ceiling was hit during extraction). Keep the recursive type well-typed (declare the `CliSchemaNode` interface explicitly for the `z.lazy`).

### 3. Storage

The extracted schema lives INSIDE the `CliConnection` JSON (full-access branch's `schema` field), which serializes into the existing `platforms.cli` TEXT column (`packages/core/src/db/schema.ts:21`). **No migration needed** — confirm `toPlatformRow`/`rowToPlatform` (`packages/core/src/repositories/platforms.ts`) round-trip a full-access connection unchanged (they already `JSON.stringify`/`CliConnectionSchema.parse` the whole `cli` object). Add a repository round-trip test with a full-access connection.

> Rationale for in-column (not a new table): `platforms.cli` already holds arbitrarily-large JSON validated on every read; a full-access schema for gh (~150-200 nodes) is well within SQLite TEXT limits. A separate `cli_schema` table would only earn its cost if the schema needed an independent lifecycle — it doesn't (it's rewritten wholesale on re-extract, like `tools` today).

## Constraints (do not violate)

- **Back-compat is sacred:** every existing declared CLI test must still pass. A stored legacy `cli` blob with no `mode` MUST parse.
- Reuse existing guards (`hasUnsafePathChars`, the credentialEnvVar denylist refine, `CliPolicySchema`, `CliToolSchema`) — do NOT reinvent them.
- No HTTP, no sync fs, typed errors, single-purpose files (`cli-schema.ts` separate from `cli-connection.ts`). Follow `docs/rules/`.
- Do NOT build the extractor, provider, or UI here. Types + storage + validation only.
