# Increment 32.6c — Backfill `surfaces[]` for top apps

> Third of the **32.6 web dogfooding fixes**. inc 30.8 shipped the catalog *shape* proven on ONE app
> (GitHub); the other 44 are thin (`supportedKinds` only, no `surfaces[]`). This backfills the
> **surface-first capability view** (available/connected cards, per-surface auth/docs/tools, and
> **catalog-driven one-click connect** via the inc-30.11 recipe) for a first batch of high-value apps.

## §0 — What / why (scope locked)

Author `surfaces[]` for a **first batch** of apps by mirroring `catalog/github/catalog.json`, then
regenerate `catalog.generated.ts`. Each backfilled app's `/app/:id` page then renders the real
surface-first view (inc 30.10) instead of the thin fallback, AND its surfaces become connectable via the
inc-30.11 recipe (`build`) + verifiable via the `verify` hints.

**First batch (10 apps — chosen for real, well-known surfaces that map cleanly onto the GitHub template):**
`gitlab, stripe, slack, notion, linear, sentry, vercel, openai, shopify, cloudflare`.
(The remaining 34 are a follow-up batch; this slice proves the backfill flow + lights up the apps a
dogfooder is most likely to click. The importer inc 30.9 can accelerate later batches.)

**Scope:** catalog DATA only (+ the mandatory regen). NO code/schema change — the schema, the render, the
connect recipe, and verify all already exist and are proven on GitHub. **Correctness bar: every authored
surface must be REAL (a true spec URL / endpoint / transport), never fabricated** — a wrong `specUrl` or
`endpoint` produces a connect that fails at verify (verify-before-commit protects the vault, but a
fabricated surface is a lie in the catalog). When a real value isn't known, **omit that surface** rather
than invent it.

## §0b — Load-bearing facts (verified against the real code)

- **Template:** `catalog/github/catalog.json` (107 lines) is the exact shape to mirror. Each surface:
  `{kind, displayName, connection, auth (≥1, first=default), build, verify?, docs?, agentGuidance?, notes?}`.
- **Schema requirements** (`catalog-schema.ts`, `AppSurfaceSchema` :139-163):
  - `build` required: `{platformIdTemplate (min1), via:"flattened"|"descriptor", credential:{kind:"api-key"|
    "bearer"|"oauth2"|"file"|"env", from:"auth"}}`. Use `platformIdTemplate:"{app}-{kind}"` (the inc-30.12
    groupability rule — distinct ids that group back under `/app/<app>`).
  - `connection` by kind: **openapi** needs `specUrl` (valid URL); **graphql** needs `endpoint` (URL);
    **mcp** needs `transport` + (`url` if http / `command` if stdio); **http** needs `baseUrl` (URL);
    **cli** needs only `kind` (+ optional `credentialEnvVar` — **must NOT end in `_TOKEN`/`_SECRET`/`_KEY`**,
    the `CliConnectionSchema` denylist).
  - `verify` by kind: openapi→`{operationId}` · graphql→`{typenameProbe:true}` · mcp→`{listTools:true}` ·
    none→`{}`.
  - `auth` array ≥1; first entry is the default. Mirror the app's top-level `auth` (e.g. gitlab
    `[{oauth2,gitlab},{token}]`).
- **openapi spec-size trap (gotchas.md):** an openapi surface whose spec is **>10 MB** fails connect at
  assembly (the `SPEC_BYTE_CAP`, fires during the streaming fetch BEFORE `select` can narrow). GitHub's
  own REST spec (12.6 MB) is exactly this — which is why GitHub's openapi surface is present-but-blocked.
  **When authoring an openapi surface, prefer a spec known to be <10 MB, or add a `select:{tags|paths}`
  (helps tool count, NOT fetch size) — and if only a >10MB spec exists, author the graphql/mcp/http
  surface instead and SKIP openapi** (record why in the app's `notes`). Validate spec size when authoring.
- **Codegen + gate:** `pnpm --filter @junction/core gen:catalog` (requires a prior
  `pnpm --filter @junction/core build` — it imports `dist` for the schema). It fail-loudly validates every
  entry against `AppCatalogEntrySchema`. The **`catalog:check` gate** (in the root `quality` script) runs
  `build && gen-catalog && git diff --exit-code` on `catalog.generated.ts` — so a backfilled surface MUST
  be regenerated + committed or `quality` (and thus CI) FAILS. **Regen is not optional.**
- **Grouping invariant (gotchas.md):** never author an app id/alias ending in a build-kind suffix
  (`-mcp`/`-openapi`/…) — the `appIdForConnection` strip depends on it. (The batch apps are all clean.)

## §1 — Per-app authoring (the work)

For each of the 10 batch apps, edit `catalog/<app>/catalog.json` to add a `surfaces[]` array, keeping the
existing top-level fields (`id`/`displayName`/`supportedKinds`/`auth`/`aliases`/`iconSlug`). Author only
surfaces whose connection details are **real and verifiable**:

- **graphql** where the app has a public GraphQL endpoint (gitlab `https://gitlab.com/api/graphql`,
  shopify admin GraphQL, linear `https://api.linear.app/graphql`, github-style). `verify:{typenameProbe}`.
- **openapi** where a **<10 MB** spec URL is real (stripe has a large but check-size spec; sentry, vercel,
  cloudflare publish OpenAPI). If >10 MB → skip + note.
- **mcp** where the app ships a hosted MCP server (transport:"http", real url) — else omit.
- **http**/**cli** as the hand-authored fallback where no schema-backed surface exists (baseUrl / a real
  CLI like `glab`, `stripe`, `vercel`), with a couple of `starterTools` or left empty per the gap-filler rule.

**Research each app's real surfaces before authoring** — this is the crux. Use each app's official API
docs for the true endpoint/spec/transport. The builder brief MUST require citing the source for each
authored `specUrl`/`endpoint`/`url` (mirrors the inc-30.9 no-fabrication `REVIEW:` discipline). When
unsure, omit the surface — a thin-but-honest entry (still connectable via 32.6a's app-level CTAs) beats a
fabricated surface.

Then: `pnpm --filter @junction/core build && pnpm --filter @junction/core gen:catalog` → commit both the
edited `catalog/<app>/catalog.json` files AND the regenerated `catalog.generated.ts`.

## §2 — Tests

- **Catalog integrity (existing gates do most of it):** `gen:catalog` fail-loud + `catalog:check` git-diff
  + the existing `catalog.test.ts` coverage tests (every provider→App, no id/alias ends in a build-kind
  suffix) must stay green. Adding surfaces must not break the `group.test.ts` reversibility invariant.
- **New assertions** (`catalog.test.ts` or a focused test): each backfilled app now has `surfaces.length >
  0`; each surface validates (`AppCatalogEntrySchema` — already enforced by codegen, but assert
  `getCatalogEntry("gitlab").surfaces` is non-empty + well-formed); the default auth mode is first.
- **Spec-size sanity (where feasible, non-network in CI):** a note/assertion that any authored openapi
  `specUrl` is expected <10 MB (documented per-app; the real fetch is a QA step, not a unit test — CI
  doesn't hit the network).

## §3 — QA (drive the real thing — this is where fabrication gets caught)

- `/app/gitlab` (and each batch app) on the **real running web server** now renders surface cards
  (available/connected), not the thin empty state.
- **Round-trip at least 2-3 surfaces against the REAL upstream** (the inc-30.11 mechanism, exactly as
  GitHub was proven): for a token-verifiable surface (e.g. a graphql `typenameProbe` or an openapi
  `verifyOperationId`), drive `connect` with a real credential → verify-before-commit either persists a
  Connected platform or cleanly refuses (auth-failed/unreachable → nothing persisted). **A fabricated
  endpoint/spec is caught HERE** (unreachable). Report which surfaces were round-tripped live vs
  authored-but-unproven.
- Any openapi surface: confirm the spec is actually <10 MB by fetching it (the gotcha) — or that it was
  correctly skipped.

## §4 — Proof of done

- `pnpm verify` + `pnpm run quality` (incl. `catalog:check`) green — the regenerated `catalog.generated.ts`
  is committed and matches.
- The 10 app pages render surface-first views on the real server.
- ≥2-3 surfaces round-tripped live against real upstreams (persist-or-cleanly-refuse proven); the rest
  authored from cited official docs. A per-app note of what was proven vs authored.

## §5 — Reviewers

`junction-mcp-contract` (surface/connection correctness per kind, the grouping invariant) +
`junction-web-reviewer` (the pages render correctly — though no web CODE changed, the DATA drives the UI) +
`ce-correctness-reviewer` (schema validity + no fabricated values — cross-check each `specUrl`/`endpoint`
against the cited source) + `junction-package-boundary` (catalog stays pure data). The
**no-fabrication check is the LEAD concern** — a reviewer must confirm every authored surface value has a
cited real source, mirroring inc 30.9.

## §6 — End-of-increment report shape

Visually testable: **Yes** — the 10 app pages showing real surface cards (vs the prior empty state), and
the live round-trip of 2-3 surfaces. Checklist: 10 apps authored from cited official docs (no fabrication) ·
each surface schema-valid · regen committed + `catalog:check` green · grouping invariant intact ·
openapi specs verified <10 MB or skipped-with-note · ≥2-3 surfaces round-tripped live · the remaining 34

## §7 — Note on batching
This slice deliberately does **10 of 44**. The remaining 34 are a mechanical follow-up (same flow, or
accelerated via the inc-30.9 importer). Authoring all 44 in one slice would be a large, error-prone,
fabrication-tempting push — proving the flow on a high-value 10 first is the correctness-over-speed call.
