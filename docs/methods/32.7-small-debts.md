# 32.7 — Small correctness/ops debts

Four small, long-recorded debts from `docs/BACKLOG.md` §1d, shipped as one increment. All are
observability/regression-hardening; none changes product behaviour for a healthy system.

**Proof-of-done:**
1. A `removeCredential` store-delete failure emits a visible warn (stderr on CLI paths) with the credential id + secretRef — **never** the secret value — and a unit test proves it (spy logger).
2. A stale `<home>/run/cred-*` dir (mtime older than 60 min) is removed at `junction serve` / `junction mcp serve` startup; a live/fresh one is NOT; a unit test proves both.

## Item 2 — `cred-*` orphan reaper

Current: a hard kill between `provider.ts:172` (writeFile ok) and `:378` (finally rm) strands `<home>/run/cred-XXXXXX` (0700 dir with a 0600 secret file). No lock marks a live dir, so a sweep MUST be age-thresholded.

Changes:
- New `packages/core/src/paths/sweep-cred-dirs.ts`: `export async function sweepStaleCredDirs(paths: JunctionPaths, opts?: { olderThanMs?: number }): Promise<number>`. Default `olderThanMs` = 3_600_000 (1 h — far above any sandbox `timeoutMs`; a live call's dir is minutes old at most). Logic: `readdir(paths.runtimeDir)` (ENOENT → return 0); for each entry starting with `"cred-"`, `stat` it (dir only); if `Date.now() - mtimeMs > olderThanMs` → `rm(dir, { recursive: true, force: true })`, count it; every fs error is swallowed per-entry (best-effort — the sweep must never break startup). If count > 0, `getLogger().warn("swept stale credential temp dirs", { count })`. Return count. Export from `paths/index.ts` (or core index) alongside `ensureRuntimeDir`.
- Call sites — fire-and-forget, AFTER the existing `ensureHome()` success, never awaited into the startup path and never failing it:
  - `packages/cli/src/commands/serve.ts` (~line 95): `void sweepStaleCredDirs(paths).catch(() => {})` (`paths` already in scope there).
  - `packages/cli/src/commands/mcp.ts` (~line 112, before the `!profileName` early-return so the synthetic-default path is swept too): `paths` is NOT in scope there — `getPaths()` only happens at :121. Use the `ensureHome()` result: `void sweepStaleCredDirs(homeResult.value).catch(() => {})` (ensureHome resolves to JunctionPaths).
  - Ordering note (fine, deliberate): the sweep's `getLogger().warn` is a noop until item 1's stderr logger is wired — items land in order in one increment.
- Tests (`packages/core/src/paths/sweep-cred-dirs.test.ts`): temp `JUNCTION_HOME`; create `run/cred-old` (backdate with `utimes` to now-2h) + `run/cred-new` (fresh) + `run/other-dir` + a stray FILE `run/cred-file` (backdated). Sweep → returns **exactly 1** (dirs-only rule: the backdated `cred-file` FILE is skipped). Assert: `cred-old` gone; `cred-new`, `other-dir`, and `cred-file` remain. Also: missing `run/` → returns 0, no throw. Pass paths explicitly (the JunctionPaths param sidesteps JUNCTION_HOME env-timing).

## Hard invariants
- Secrets never appear in any log line, test output, or error message (secretRef the HANDLE is fine; the secret VALUE never).

- core stays HTTP-free and edge-free; the stderr logger lives in `cli` (core only talks to the `Logger` interface).

- `serve.mjs` default behaviour (as launched in production) must be byte-identical; the smoke test (`pnpm run web:smoke`) must still pass.
