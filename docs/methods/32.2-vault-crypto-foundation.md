# Increment 32.2-foundation — Shared vault-crypto foundation

> **NOTE ON NUMBERING:** this is the **blocking foundation slice** of the 32.3/32.4/32.5 wave, NOT the
> deferred "32.2 heavy-analyzers" (knip/semgrep/CodeQL — those stay deferred). To avoid a number
> collision it ships as part of the 32.3 PR's first commit OR its own tiny PR titled
> `feat(inc32): shared vault-crypto foundation`. It touches only `core/credentials`. Do not confuse
> the two 32.2s: this file = the crypto extraction; the deferred one = CI analyzers.

## §0 — What / why (scope locked)

32.3 (master-key rotation) and 32.4 (vault backup) both need the **exact same** AES-256-GCM + scrypt
primitives that `encrypted-file-store.ts` and `master-key.ts` already implement privately. That's the
**rule of three** (file-store + rotate + archive) — the trigger to DRY these primitives into a shared,
exported module *now*, before two more copies exist. This slice is pure extraction + one genuinely-new
helper; **no behavior change** to the existing store or key resolver.

Extract/export (from the exact current code, verified this session):

1. **`gcmEncrypt` / `gcmDecrypt`** — the AES-256-GCM pair currently inlined as `encryptRecord` /
   `decryptRecord` (`encrypted-file-store.ts:81-107`). Generalize the AAD from "always the secretRef"
   to an **explicit `aad: Buffer` parameter** (the store passes `Buffer.from(secretRef)`; the archive
   passes its header bytes; rotate re-encrypts with `Buffer.from(secretRef)` unchanged).
2. **`deriveKeyFromPassphrase(passphrase, salt) → ResultAsync<Buffer, CredentialError>`** — currently
   private in `master-key.ts:52-74`. **DO NOT re-declare the scrypt params** (`N:131072, r:8, p:1,
   maxmem:256*1024*1024`) anywhere else — export this one function; it is the single source of the
   `maxmem` gotcha fix. 32.4 export/import call it; rotate's passphrase-tier reinstall calls it.
3. **`writeFile0600(target, data) → Promise<void>`** — atomic tmp→rename at 0600
   (`master-key.ts:118-125`). Both 32.3 (sidecar/backup/new-key writes) and 32.4 (archive write) reuse
   it so **every new sensitive file is 0600 by construction** (the inc-31 world-readable-file gotcha —
   `gotchas.md`).
4. **`EncFileSchema`** + its `EncRecordSchema` / `EncFile` / `EncRecord` types
   (`encrypted-file-store.ts:17-28`) — 32.3 rotate reads/writes the whole enc-file map directly
   (decrypt-all → re-encrypt-all), so it needs the schema.
5. **NEW: `resolveMasterKeyWithTier(paths, env) → ResultAsync<{ key: Buffer; tier: MasterKeyTier },
   CredentialError>`** — the current `resolveMasterKey` (`master-key.ts:172`) computes the tier
   internally but **discards it**, returning only the key. 32.3 rotation MUST know the tier (env /
   keyring / file) to reinstall the new key at the **same posture** and to refuse env-raw. This is the
   one net-new primitive.

**`MasterKeyTier`** discriminates the 4-tier ladder more finely than "env/keyring/file" because rotation
policy differs *within* env:
```ts
export type MasterKeyTier =
  | { kind: "env-raw" }                 // JUNCTION_MASTER_KEY = a raw 32B key → CANNOT reinstall (env is read-only to us)
  | { kind: "env-passphrase" }          // JUNCTION_MASTER_KEY/_FILE = a passphrase → scrypt; reinstall = re-derive w/ fresh salt
  | { kind: "keyring" }                 // OS keyring Entry("junction","__master_key__")
  | { kind: "file" }                    // auto-generated ~/.junction/master.key (Tier 3)
```
(`env-raw` vs `env-passphrase` matters: env-passphrase CAN rotate — re-derive under a fresh salt file;
env-raw cannot — the raw key value lives only in the operator's environment. See 32.3 §fork.)

## §0b — Load-bearing facts (verified against the real code this session)

- `encryptRecord`/`decryptRecord` are **module-private** in `encrypted-file-store.ts` today; the store's
  `createEncryptedFileStore` closure calls them. After extraction the store imports `gcmEncrypt`/
  `gcmDecrypt` from the new module and passes `Buffer.from(secretRef)` as `aad` — **byte-identical**
  behavior (same IV-per-call, same AAD, same tag-before-final). The existing `credentials.test.ts`
  round-trip + tamper + AAD-swap tests are the regression guard — **they must stay green with zero edits**.
- `deriveKeyFromPassphrase` currently returns `ResultAsync<Buffer, CredentialError>` with
  `{kind:"key-unavailable", cause}` on scrypt error — keep that exact contract.
- `writeFile0600` uses `randomBytes(8)` for the tmp suffix and `chmod` belt-and-suspenders — keep verbatim.
- **The crypto extraction itself needs no new error kind** — the moved primitives map onto existing
  `CredentialError` (`io-failed`/`key-unavailable`/`decrypt-failed`). **BUT** (spec-flow finding C2) both
  32.3 and 32.4 would otherwise add new kinds to `errors/index.ts` AND edit the exhaustive
  `formatCredentialError` (`cli/format.ts:155-172`) **in parallel** — a hidden `touches` collision (two
  builders editing the same exhaustive switch → conflict + a transiently non-exhaustive switch at
  integration). **RESOLUTION: this foundation slice — which lands FIRST, alone — extends the error union
  + the formatter ONCE, exhaustively, so the two leaves only *use* the kinds, never edit the switch.**
  Add to `CredentialError` (`errors/index.ts`):
  ```ts
  | { kind: "rotate-refused"; reason: string }     // 32.3: keyring/env-raw/empty-vault refusal (carries the explanation)
  | { kind: "rotate-failed"; cause: unknown }      // 32.3: a rotation step failed (verify/decrypt/io)
  | { kind: "export-failed"; reason: string }      // 32.4: export precondition/resolve failure
  | { kind: "import-failed"; reason: string }      // 32.4: wrong-pass/tamper/parse/collision failure (generic — no oracle)
  ```
  and the matching arms in `formatCredentialError`. This is why `touches` includes `core/errors` +
  `cli/format`. (`reason`-carrying kinds so the human/`--json` message is self-contained; `rotate-failed`
  keeps `cause` opaque — never a secret.)
- **No migration.** Pure code.

## §2 — Tests (Vitest, in `packages/core/src/credentials/`)

New `vault-crypto.test.ts`:
- `gcmEncrypt`→`gcmDecrypt` round-trips for a given key+aad; **fresh IV** each call (two encrypts of the
  same plaintext differ in `iv`/`ct`).
- **AAD binding:** a record encrypted with `aad=A` fails `gcmDecrypt(key, B, record)` (throws) — proves
  the archive-header AAD and the secretRef AAD can't be swapped.
- **tag tamper:** flip one byte of `tag`/`ct` → `gcmDecrypt` throws.
- `deriveKeyFromPassphrase`: 32-byte output; **deterministic** for a fixed salt; differs for a different salt.
- `writeFile0600`: file exists at mode `0o600`; content byte-equal; overwrites atomically (no `.tmp` left).

New `master-key-tier.test.ts` (or extend `master-key-tier2.test.ts`):
- `resolveMasterKeyWithTier` reports `{kind:"env-raw"}` for a 32B base64/hex env key;
  `{kind:"env-passphrase"}` for a non-raw-shaped env value; `{kind:"file"}` for the Tier-3 auto-gen
  path; `{kind:"keyring"}` for a mocked 32B keyring entry (reuse the tier2 hoisted mock).
- `resolveMasterKey` still returns the **same key** as `resolveMasterKeyWithTier(...).key` (delegation
  regression).

**Existing `credentials.test.ts` must stay 100% green with NO edits** — that's the proof the extraction
is byte-identical.
