# Increment 32.4 — Vault backup / recovery

> Leaf slice of the 32.x wave. A **portable, passphrase-wrapped** archive of your credentials so you can
> back up and move a junction vault between machines/backends. **The bar:** round-trips every credential
> byte-identically across BOTH backends and any {file↔keyring} combination, a wrong passphrase or a
> tampered archive writes NOTHING, and **no plaintext secret ever touches disk unencrypted** (not the
> archive, not a temp file).

## §0 — What / why (scope locked)

- `junction vault export --out <path>` → writes a single self-contained **`.jvlt`** archive: a
  passphrase-wrapped (scrypt→AES-256-GCM) blob containing the operator's credentials (secrets resolved)
  + the platforms they reference.
- `junction vault import <path>` → reads a `.jvlt`, prompts for the passphrase, decrypts, and reconstructs
  the credentials + platforms in the target vault.

**Backend-AGNOSTIC (the key architectural fact):** export reads plaintext via the live
`CredentialStore.get(secretRef)` and import writes via `store.set` / `addCredential` — both go through
the `CredentialStore` interface, which works IDENTICALLY on keyring and encrypted-file backends. So a
vault exported from a keyring machine imports cleanly onto a file-backend machine and vice-versa. The
master key is NEVER in the archive — the archive is wrapped under the operator's chosen **export
passphrase**, independent of the source machine's master key.

## §0a — FORKS RESOLVED (user, this session)

- **Scope: credentials + their platforms** [default]. Every exported credential + the `Platform` config
  rows it references (needed as the FK on import; platforms are secret-free config). **`--include-profiles`**
  opts profiles in (routes/namespacing/toolFilter — they reference credential ids, remapped on import).
- **oauth2 INCLUDED** (it's the complex part — see §0b; recommended include).
- **Collision: skip** [default] — `--on-collision skip|overwrite|error`. Import is additive + resumable.
- **Missing secret on export: FAIL** [default] — if a credential's `store.get(secretRef)` returns `null`
  (the secret vanished from the store), export FAILS with a clear error naming the credential.
  **`--skip-missing`** downgrades to skip-that-credential-and-continue (records it in the summary).

## §0b — Load-bearing complexity: the oauth2 4-ref credential

Most credentials hold ONE secret (`secretRef`). An **oauth2** credential holds up to **FOUR** store refs
(`schema/credential.ts`): `Credential.secretRef` (access token) + `oauthMeta.refreshTokenRef` +
`oauthMeta.clientIdRef` + `oauthMeta.clientSecretRef`. Export must resolve ALL present refs via
`store.get`. Import must mint FRESH refs and `store.set` each, then persist the credential with the new
refs.

**`addCredential` REFUSES oauth2** (`add-credential.ts:84` — the runtime guard; it stores exactly one
plaintext secret at one ref). So import needs a **dedicated oauth2 path** that bypasses `addCredential` —
modelled EXACTLY on the proven `persistOAuthTokens` (`source-runtime/oauth-connect.ts:414-552`), which is
the real code that already does a fresh oauth2 insert:
1. mint fresh `id` + fresh `secretRef` + fresh refs for each present oauth ref — all via
   **`newCredentialId()`** (the single ULID swap point, `ids/index.ts` — M1; do NOT hand-roll `ulid()`).
2. **VALIDATE FIRST, BEFORE any `store.set` (H1):** assemble the full `Credential`
   (`kind:"oauth2"`, new refs in `oauthMeta`, preserved metadata `providerId`/`authMode`/`scopes`/
   `expiresAt`/`needsReauth`/`obtainedAt`) and `CredentialSchema.safeParse` it — exactly as
   `persistOAuthTokens:464` does. A malformed platformId/metadata must fail HERE, before secrets touch the
   store (else store.set writes plaintext that only fails at DB insert → stranded store entries).
3. **the platform row must already exist** — import upserts ALL referenced platforms FIRST (§3 step 4),
   for oauth2 credentials too (FK `credentials.platformId → platforms.id`). The oauth2 path does not
   re-check kind-compat (matching `persistOAuthTokens`, which also skips it — the matrix isn't the
   authority for a mint-path insert; `CredentialSchema` is).
4. `store.set(newSecretRef, accessToken)` + `store.set(newRefreshTokenRef, refreshToken)` + client-id/
   secret if present.
5. `credentialsRepo.create(credential)` — **`create` accepts a full Credential incl. `oauthMeta`**
   (verified `repositories/credentials.ts:48` JSON-stringifies oauthMeta; `persistOAuthTokens:490`
   exercises this). (`setOAuthTokens` is for the post-refresh merge, NOT a fresh insert.)
6. on any store.set/create failure, best-effort-delete **ALL refs already written** (mirror
   `persistOAuthTokens`'s hoisted `written` guard — up to 4 refs, not just secretRef), then propagate —
   per-credential fail-safe. **Kill-safety is best-effort (H3):** a SIGKILL between `store.set` calls and
   `create` leaves orphaned refs no cleanup runs on. "Resumable" (§3 step 6) means resumable across a
   RETURNED Err, not a SIGKILL — stated so the atomicity claim isn't overstated.

**Non-oauth2 credentials** (api-key/bearer/env/file) import through the normal **`addCredential`** path
(fresh id + fresh secretRef minted inside it) — reuse the validated, kind-compat-checked, duplicate-guarded
path rather than reimplementing it. (This means the platform must be upserted FIRST so `addCredential`'s
kind-compat matrix + duplicate guard have the platform row.)

## §0c — Load-bearing facts (verified)

- **No migration** — import reuses `platforms.upsert` + `addCredential`/`credentials.create` +
  (profiles path) the existing profile repo ops, all writing existing columns only.
- `platforms.upsert` (`repositories/platforms.ts:78`) replaces all fields on id-conflict — exactly the
  FK-first upsert import needs.
- **Error kinds** `export-failed`/`import-failed` are added in the **32.2 foundation slice** (spec-flow
  C2 — this leaf does NOT edit `errors/index.ts`/`format.ts`). This slice only CONSTRUCTS them.
  Wrong-passphrase/tamper both map to `import-failed` with a generic reason — never distinguish "wrong
  passphrase" from "tampered" (no oracle); both are "could not decrypt archive".

### Profiles path (`--include-profiles`) — reworked after doc-review (2 CRITICALs)

Profiles carry `SourceRef[]`; each route's `credentialId` is **optional** (public/no-auth sources have
none — verified `profiles.ts:120`, `source-ref.ts`). On import, credential ids are FRESH, so a route's
`credentialId` must be **remapped**. The **`idMap` is `_srcId → resolvedTargetId`** and it MUST record an
entry for **every** credential the manifest carried, not only newly-added ones:

- **C2 fix — collision-SKIP is NOT a drop.** A collision-skipped credential EXISTS on the target (that's
  why it collided). Its route must remap old `_srcId → the EXISTING target credential's id`
  (found via `credentials.forPlatform(platformId)` matching `{platformId, account}`), NOT be dropped.
  Only a credential that was **missing/failed** (no target row at all) drops its route (with a summary
  note). So the map is populated in THREE cases: added (→ new id), collision-skip/overwrite (→ existing/
  replaced id), and missing/failed (→ no entry → route dropped). A route whose `_srcId ∉ idMap` drops
  uniformly (covers missing + `--skip-missing` export — I5/M3).
- **C1 fix — profile name UNIQUE + no upsert.** `profiles.name` is `.unique()` (`db/schema.ts:47`) and
  the profiles repo has **no upsert** — only `create` (plain INSERT, `profiles.ts:133`). Importing a
  profile whose `name` already exists throws SQLITE_CONSTRAINT_UNIQUE → an opaque `constraint-violation`
  DbError → an ugly mid-import abort. **DECISION (fold in): `--include-profiles` import applies the SAME
  `--on-collision` policy to profiles, keyed on `profile.name`:**
  - `skip` [default] → a profile whose name exists on target is **skipped** (its credentials still
    imported above; only the profile wrapper is skipped) + a summary note.
  - `error` → abort with `import-failed: profile "<name>" already exists`.
  - `overwrite` → out of scope for v1 (a profile has cascade-on-delete source_refs — overwriting risks
    dropping live routes). Treat `overwrite` for profiles as `skip` + a note, OR reject `overwrite
    --include-profiles` explicitly. **RECOMMEND: reject the combination with a clear message** ("profile
    overwrite is not supported; remove the profile first or use skip"). Simpler + safe.
  A fresh imported profile also mints a fresh profile `id` (`newSourceRefId`/profile id via the repo) —
  no `id` collision by construction; only `name` collides, handled above.
- Profiles import **LAST** (after all credentials, so the idMap is complete). A route with a dropped
  credential is omitted from the created profile (never a dangling FK — `source_refs.credentialId` is
  RESTRICT).

## §1 — Archive format (`.jvlt`)

A single binary file: `[magic "JVLT"(4)][version u8][kdf u8][salt(16)][iv(12)][tag(16)][ciphertext…]`.
- **magic** `4a 56 4c 54` ("JVLT") — reject anything else with `import-failed: not a junction vault archive`.
- **version** `1`. **kdf** `1` = scrypt (the foundation params).
- **AAD = the header bytes** (magic+version+kdf+salt+iv, i.e. everything before the tag). This binds the
  ciphertext to its header so a spliced/downgraded header fails the tag check.
- **key** = `deriveKeyFromPassphrase(passphrase, salt)` (foundation).
- **plaintext** = `JSON.stringify(manifest)` (below), UTF-8.
- Written 0600 via `writeFile0600` (tmp→rename). **The `.jvlt` is a BEARER SECRET** — export prints a
  warning saying so.

**Manifest** (the decrypted JSON — Zod-validated on import with a `VaultManifestSchema`):
```ts
{
  v: 1,
  exportedAt: string,                      // ISO; informational
  idMap?: Record<string,string>,           // present only with --include-profiles: old credId → (filled at import)
  platforms: Platform[],                    // secret-free config
  credentials: Array<{
    // metadata (NOT the DB id — a fresh one is minted on import)
    platformId: string, account: string, kind: CredentialKind,
    oauthMeta?: OAuthMeta,                  // WITHOUT the *Ref handles (those are source-machine-local); see below
    lastVerifyResult?: ..., lastVerifiedAt?: ...,
    // the RESOLVED secrets (the sensitive payload — only ever inside the encrypted blob)
    secret: string,                         // access token / api-key / bearer / file-content / env-value
    refreshToken?: string,                  // oauth2
    clientId?: string, clientSecret?: string, // oauth2 BYO
    _srcId: string,                         // the source-machine credential id (for profile remap only)
  }>,
  profiles?: Profile[],                     // only with --include-profiles; routes reference _srcId, remapped on import
}
```
**Note the ref-stripping:** `oauthMeta` in the manifest carries the *metadata* (providerId/authMode/
scopes/expiresAt/needsReauth/obtainedAt) but NOT `refreshTokenRef`/`clientIdRef`/`clientSecretRef` —
those are source-machine store handles, meaningless on the target. The actual token VALUES ride in the
sibling `refreshToken`/`clientId`/`clientSecret` fields (inside the encrypted blob); import mints fresh
refs and rebuilds `oauthMeta` with them. This keeps handles machine-local and secrets in exactly one place.

## §2 — export (`packages/core/src/credentials/export-vault.ts`)

`exportVault({repos, store, passphrase, includeProfiles, skipMissing}) → ResultAsync<Buffer,
CredentialError>`:
1. `repos.credentials.list()` → for each: resolve `store.get(secretRef)`; for oauth2 also resolve
   `refreshTokenRef`/`clientIdRef`/`clientSecretRef` where present.
   - any `get` returns `null` → **fail** (`export-failed: credential <platform>/<account> secret missing`)
     unless `skipMissing` (then skip that credential + record it).
2. Collect the referenced `platformId` set → **`repos.platforms.list()` filtered to that set** (NOT
   `platforms.get` each — `get` Errs `not-found` on a dangling FK and would hard-fail the whole export,
   I5). Then **orphan check:** if any credential's `platformId` isn't in the listed platform set (its
   platform row was deleted), `export-failed: credential <platform>/<account> references a missing
   platform` — unless `--skip-missing` (skip that credential + note it). Embed the resolved platforms.
3. If `includeProfiles`: `repos.profiles.list()` → embed; build `_srcId` per credential.
4. `manifest = {v:1, exportedAt, platforms, credentials:[…], profiles?}`.
5. `key = deriveKeyFromPassphrase(passphrase, salt=randomBytes(16))`; build header; `rec = gcmEncrypt(key,
   headerBytes, JSON.stringify(manifest))`; assemble `[header][tag][ct]`.
6. **Wipe plaintext buffers** (`buf.fill(0)` on the derived key + any Buffer holding a secret) after
   assembly — best-effort hygiene (JS strings can't be zeroed; documented limitation, mirror the inc-24
   note).
7. Return the archive Buffer. The CLI writes it 0600 via `writeFile0600(outPath, buffer)`.

**Passphrase (interactive):** export prompts for the passphrase **twice** (confirm) via `@clack/prompts`
password input; headless `--passphrase-stdin` reads it once from stdin (no confirm — headless trusts the
caller). Empty passphrase → refuse.

## §3 — import (`packages/core/src/credentials/import-vault.ts`)

`importVault({repos, store, archive, passphrase, onCollision, includeProfiles}) → ResultAsync<ImportSummary,
CredentialError>`:
1. Parse header; check magic/version/kdf → else `import-failed: not a junction vault archive`.
2. `key = deriveKeyFromPassphrase(passphrase, salt)`; `gcmDecrypt(key, headerBytes, {iv,tag,ct})` — a
   throw (wrong passphrase OR tamper) → `import-failed: could not decrypt archive (wrong passphrase or
   corrupted file)`. **NOTHING written.**
3. `VaultManifestSchema.parse(JSON.parse(plaintext))` — malformed → `import-failed: invalid archive
   contents`. NOTHING written.
4. **platforms FIRST** (`platforms.upsert` each) — the FK. On `--on-collision`:
   - `skip`: `platforms.get(id)` exists → leave it (platforms are config; skip = don't overwrite).
   - `overwrite`: upsert unconditionally.
   - `error`: exists → abort `import-failed: platform <id> already exists`.
5. **credentials** — for each, check `credentials.forPlatform(platformId)` for an existing
   `{platformId, account}` (the duplicate key):
   - collision + `skip` → skip, record in summary.
   - collision + `error` → abort.
   - collision + `overwrite` → **remove the existing credential first** (`removeCredential`) then add the
     imported one. **CAVEAT 1 (in-use):** `removeCredential` RESTRICT-fails if the credential is in use by
     a profile route (`in-use` DbError) — surface a clear `import-failed`/summary entry ("credential in
     use by a profile; cannot overwrite — remove the route first or use --on-collision skip"), do NOT
     force-delete. **CAVEAT 2 (H2 — oauth2 4-ref orphan):** `removeCredential` deletes ONLY
     `credential.secretRef` (`remove-credential.ts`), NOT the oauthMeta refs. Overwriting an existing
     **oauth2** credential would strand up to 3 refs (refreshTokenRef/clientIdRef/clientSecretRef) in the
     store. **DECISION (fold in):** the overwrite path, when the existing credential is oauth2, resolves +
     `store.delete`s all present oauthMeta refs before/alongside `removeCredential` (a small
     `removeOAuthCredentialRefs` helper) so overwrite doesn't accumulate orphaned secrets. (This is a
     pre-existing `removeCredential` gap; 32.4's overwrite path must not inherit it.)
   - no collision → add:
     - **non-oauth2** → `addCredential({platformId, account, kind, secret}, platform, store,
       repos.credentials)`.
     - **oauth2** → the dedicated path (§0b): mint refs, `store.set` each, `credentials.create(cred)`.
   - build the `_srcId → newId` map entry.
6. **ATOMICITY = additive + per-credential fail-safe**, NOT global all-or-nothing. Each credential's
   store+DB write is cleaned up on a RETURNED Err at the credential level (mirror `addCredential`'s
   cleanup-on-DB-fail; the oauth2 path cleans all up-to-4 refs). A mid-import Err leaves already-imported
   credentials in place; **re-running with `skip` resumes** (the imported ones now collide→skip).
   **Caveat (H3):** "resumable" means resumable across a returned Err — NOT across a SIGKILL. A kill
   between an oauth2 credential's `store.set` calls and its `create` strands refs no cleanup runs on (same
   best-effort limit as `persistOAuthTokens`). Not a plaintext-on-disk leak (encrypted at rest); recorded.
   (A strict temp-DB-swap all-or-nothing is heavier and out of scope — deferred fork in `revisit-when.md`.)
7. If `includeProfiles`: import profiles LAST, remapping each route's credential id via the `_srcId →
   newId` map; drop routes whose credential was skipped/missing (summary note).
8. Return `ImportSummary = {platforms:{added,skipped}, credentials:{added,skipped,overwritten,failed:[…]},
   profiles?:{…}}` — metadata only, never a secret.

## §4 — CLI surface (edits `packages/cli/src/commands/vault.ts` — created by 32.3)

```
junction vault export --out <path> [--passphrase-stdin] [--include-profiles] [--skip-missing] [--json]
junction vault import <path>       [--passphrase-stdin] [--on-collision skip|overwrite|error] [--include-profiles] [--json]
```
- `export`: `openDbAndStore(json)`; **`--out` guardrail (C4):** if the resolved `--out` path is INSIDE
  `paths.home` (`~/.junction`), **refuse** — `export-failed: write the archive outside ~/.junction; it is
  a bearer secret and the home directory is exposed to sandboxed sources`. (A `.jvlt` next to
  credentials.enc.json would sit in the sandbox-visible home; `sandbox/policy.ts` only whitelists
  credentials/master-key files, not arbitrary home files.) Prompt passphrase (×2 confirm interactive, or
  `--passphrase-stdin`); `exportVault(...)`; `writeFile0600(out, buf)`. Human output: `Exported N
  credentials + M platforms to <path>. ⚠ This archive is a BEARER SECRET — anyone with the file +
  passphrase can use these credentials. Store it securely.` `--json`: `{ok:true, out, credentials:N,
  platforms:M, skipped?:[…]}`.
- `import`: `openDbAndStore(json)`; read archive bytes; prompt passphrase (or `--passphrase-stdin`);
  `importVault(...)`; print the `ImportSummary`. `--json`: `{ok:true, summary}`. Wrong-passphrase/tamper/
  invalid → `{ok:false, error:"could not decrypt archive …"}` and exit 1, **nothing written**.
- **Headless contract — NEVER hang (I3):** if stdout is non-TTY OR `--json` is set, and
  `--passphrase-stdin` is ABSENT, **fail fast** — `export-failed`/`import-failed: passphrase required; pass
  --passphrase-stdin in non-interactive mode` (do NOT drop into an interactive `@clack` prompt that would
  hang an agent). With `--passphrase-stdin`, an empty/EOF stdin (`< /dev/null`) → the same clean refusal,
  never a hang. Every interactive path keeps a headless equivalent (project rule). A headless test drives
  both with `< /dev/null` and asserts a prompt exit, not a hang.
- Both: NEVER print a secret/token/secretRef. The passphrase is read from stdin/prompt, never argv.

## §5 — Tests (round-trip + adversarial, both backends, oauth2 MANDATORY)

Core `export-vault.test.ts` + `import-vault.test.ts` (+ a `roundtrip` integration test), harness
`withTempHome` + a real `createEncryptedFileStore` AND a keyring-backed store where available:

- **Round-trip per backend:** seed api-key + bearer + env + file + **oauth2 (all 4 refs)** credentials +
  2 platforms → export → NEW temp home → import → every secret + all 4 oauth refs resolve to the SAME
  plaintext; platforms present; credential kinds/accounts/oauthMeta metadata preserved.
- **Cross-backend:** export from a **file** home → import into a **keyring** home (and reverse) → secrets
  identical. (Skips gracefully if keyring unavailable, like the existing KeyringStore tests.)
- **Wrong passphrase** → `import-failed`, ZERO writes (assert the target store + DB empty afterward).
- **Tamper**: flip a byte in the header, the tag, and the ciphertext (three cases) → tag check fails →
  `import-failed`, ZERO writes.
- **secret-never-on-disk:** grep the produced `.jvlt` bytes (`grep -a`) for a sentinel secret string →
  ABSENT (it's inside the AES blob). Also assert no plaintext temp file is left in the home/run dir
  during export/import.
- **missing-secret on export:** delete a credential's store entry → export FAILS naming it; `--skip-missing`
  → succeeds, that credential absent from the archive + in the summary.
- **collision policies:** import an archive whose creds already exist → `skip` leaves existing untouched +
  imports only new; `error` aborts on first collision; `overwrite` replaces (and an in-use credential →
  clean `in-use` surface, no force-delete).
- **partial-import resume:** inject a mid-import failure (e.g. store.set throws on the 3rd credential) →
  first 2 imported, re-run with `skip` → completes, no dupes.
- **profiles (reworked):** `--include-profiles` → routes' credential ids remapped: an ADDED credential's
  route → new id; a **collision-SKIPPED** credential's route → the EXISTING target id (NOT dropped — C2);
  a MISSING/failed credential's route → dropped with a note. A **profile whose name already exists** on
  target → skipped (default) / aborts (`error`) / rejected-combination (`overwrite`) — C1; the
  profile's credentials still import. A public-source route (`credentialId` undefined) imports unchanged.
- **interrupted-rotation-then-export (C4 cross-slice property):** interrupt a 32.3 rotation (leave a
  `.master.key.old` sidecar), then `vault export` → `openDbAndStore`→`createCredentialStore` heals the
  rotation first (32.3's hoisted recovery), export succeeds against the recovered vault. (Proves the two
  slices compose safely.)
- **--out inside home** → export refuses (C4).
- **headless no-hang** → `export`/`import` with non-TTY + no `--passphrase-stdin` exits with the
  passphrase-required error, never hangs (I3); `--passphrase-stdin < /dev/null` → clean refusal.
- **oauth2 dedicated path:** assert the imported oauth2 credential has FRESH refs (different ULIDs than
  the source) all resolving correctly, and `addCredential` was NOT used for it (it would have refused).
